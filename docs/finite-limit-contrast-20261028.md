# A bounded raised-limit software contrast

The EX sequence produced a stronger software observation than the earlier all-clean40→200→40 experiment: while both sampled alternate limits were200, **23 clean-bracket rows had C7=1 and H0 low16 above40**. The maximum sampled score was76 at cycle35. The observation completed55 clean cycles and one quiescent cycle; quiescent row19 remains distinct. Last retained cycle56 had H52 and full AA0/AC2, scan1, root context and selector1 consistent with the source's alternate-limit mode. This is a sampled software witness. It does not prove the decision-time FP register, comparator invocation, emitted light or permanent prevention.

The intervention changes two source uses of the same halfword: alternate comparison threshold and inclusive publication capacity. A limit200 path can publish ordinals0..200 before incrementing to201; limit40 can publish0..40 before incrementing to41. A larger latch or a larger record prefix therefore cannot isolate the comparison predicate. The source-compatible mode in the last retained row is not projected backwards into the22 other compact witness rows whose complete AA/AC context was not retained.

## Finite writer admission

The earlier writer required both endpoint diagnostics to equal the current calculation. Positive source evidence shows that the stock updater can refresh only one endpoint, then update shared current diagnostics. Requiring the alternate endpoint to equal the newest current calculation can consequently refuse a source-compatible retained endpoint. The [EZ source model](../research/panel-idle-20261026/overnight/selective-endpoint-limit-design-20261028ez/README.md) derives exactly72 possible alternate values under pinned coefficients/base/reference/cap/floor; it does not admit every integer in the surrounding range. In-range gaps still refuse. The ordinary endpoint must continue to match the current calculation.

The [FA implementation](../research/panel-idle-20261026/overnight/selective-endpoint-limit-writer-20261028fa/README-wrapper.md) retains fixed callbacks/profile/context, clean full-R admission, exact source-model membership, transaction stability, pending-IN obligations, packet address/value and no retry. Only the alternate-endpoint membership guard changes. A profile, mode, endpoint, identity or phase mismatch still stops the transaction. A post-write refusal conservatively retains the possibility that the limit changed; it does not send an automatic restoration packet.

The [EX coordinator review](../research/panel-idle-20261026/overnight/limit-rechallenge-trial-20261028ex/reviews/coordinator-review/README.md) verifies pinned-source admission, failure stops, fresh recomputation of the EY observation proof before a later EB request, and zero automatic restore/recovery/retry. The [EW200 recovery guard](../research/panel-idle-20261026/overnight/limit-rechallenge-recovery-review-20261028ew/README.md) admits only a separately accepted, stable200 fault snapshot in a known completed phase. It does not infer current phase from a rejected onset reader. Unknown phase permits no additional OUT, read header, restore or blind reset. Known fault classification and completed protocol phase are separate questions.
