# Export coverage, privacy and reproducibility

The export inventories the complete retained Samsung work tree, not only its latest external-research phase. `research/` preserves substantive authored reports, reviews, annotated instruction excerpts, function maps, protocol analyses, reproducers, experimental source, tests, runbooks, rollback instructions and sanitized scientific observations. Negative and superseded results remain beside later findings.

Exporter policy version `2026-10-28.3` closes a gap discovered before the new firmware work was exported: `private/` is now excluded at **any depth**, including mixed workstreams with authored source beside private plans. Known sensitive plan/configuration basenames are independently denied if moved outside that directory. These path-denied records are not opened or content-hashed for export; their original names, content hashes and individual sizes are absent from public disposition rows. Aggregate omitted byte counts remain available. A known saved token can still be read solely by the existing redactor to remove copies from otherwise eligible historical text; that credential is never an export input or manifest value.

[The summary](../manifests/export-summary.json) gives exact file/byte counts and workstream coverage. [Source dispositions](../manifests/source-dispositions.json) maps each input to its disposition and, where permitted, original SHA-256. Published records also have a public path and public-byte hash. [The omission index](../manifests/omissions.json) enumerates withheld artifacts with reason and an opaque source ID; nonprivate omissions can also retain size and hash. A source ID is SHA-256 of the original relative filename; withheld filenames are absent so an index cannot expose a private viewing title or credential filename. Published older commit-pinned manifests retain their historical policy; this change does not rewrite them.

Omitted categories include credentials and private access state, local network administration, raw authentication/session/transport envelopes, private media history and photos, whole firmware/vendor binaries, encrypted key blobs, compiled payloads, SDK/runtime/build caches, upstream checkouts that are linked instead, and whole-library mechanical disassembly. Authored function excerpts and their analysis are retained. Private binary inputs can be reacquired independently and verified by hash where lawful and available; they are not recoverable from this repository.

The private basename denial includes actual decrypted metadata/section plans, TLS configuration and connection records, listener-port records, raw authenticated header/envelope files, and acquired item key files. Whole decrypted firmware, unpacked filesystems, partition dumps, raw OEM/source acquisition trees, and per-binary `.records` chunk directories are also path-denied regardless of extension or apparent text format. An extensionless kernel or an extracted OEM configuration file is not authored research source. Existing upstream-checkout/license boundaries remain in force; original authored acquisition tools and analysis/tests outside raw acquisition trees remain eligible. Mixed JSON inventories replace private-reference rows with a metadata-omission marker, and nonce/salt/signature-value keys receive defensive redaction. These rules supplement human review; they do not claim to recognize arbitrary secrets under unknown names.

Raw command envelopes are transformed into labeled scientific observations where possible. Payload-staging commands, encoded binary copies, account/network queries and unrelated application log rows are removed. Full VLOG text is reduced to controller/display/HDMI/USB scientific rows. This does not create a byte-identical original, and the manifest records that distinction.

Redactions normalize the researcher's local username, replace RFC1918 addresses with documentation addresses, replace boot/session UUIDs with a sentinel, zero MAC addresses, remove known saved-token values, omit credential-shaped fields, anonymize media labels, and omit long encoded payloads. Version-zero protocol UUIDs remain outside the boot/session UUID pattern. The exact standard GPT Linux filesystem type GUID is explicitly preserved as public protocol/type metadata; no boot/session identity receives an exception. Local absolute evidence roots become `${S95F_EVIDENCE_ROOT}`. This placeholder is explanatory text inside historical code, not a claim that all old scripts support environment configuration.

No symlink is dereferenced into the export. Each is recorded as an omitted reference. The public tree has no executable file bits on retained historical artifacts. Relative layout is preserved and filename privacy rewrites are consistently applied to links and text. References to intentionally withheld inputs can remain; use the disposition manifest and nearby input manifests to understand those dependencies.

The exporter is included in [tools/export_public.py](../tools/export_public.py). Given access to the private evidence snapshot, invoke it with explicit source and destination arguments outside that source tree. Publication tools never infer credentials, connect to a television or run retained experiments. The ongoing source tree can change; snapshot hashes identify the exact bytes exported rather than claiming an atomic capture of an active investigation.

Its schema is `{"labels": ["private label"], "names": [["private alias", "subject_a"]]}`. The actual labels and alias dictionary are omitted because bundling them would expose the identities being removed. Without that private configuration, the generic exporter cannot reproduce the exact public aliasing or claim to sanitize arbitrary media/account content. The public manifests verify the resulting bytes independently of the private configuration.

## UUID privacy successor

Exporter policy `2026-10-28.4` fixes a historical boundary defect: the old UUID regex used word boundaries, so literal JSON `\n` or `\u0022`, nested escapes and prose immediately before an identity could hide it. Canonical version 1–5/variant UUID shapes now match without those boundaries. The independent verifier checks archived research under the same policy separately from the exporter and reports only file/line, never the matched value. The existing redaction sentinel and exactly the standard GPT Linux filesystem partition-type GUID are admitted; that public type identifier is scientific metadata, not a runtime identity. There is no path-wide or boot/session exception.

The [correction ledger](../manifests/uuid-privacy-correction.json) records 42 identity substitutions in exactly 24 archived files, made from the preserved candidate's public bytes. Original source hashes remain unchanged, current public hashes and package manifests are updated, and every other archive byte is preserved. All five earlier fixtures, the sixth fixture and three upstream notices are byte-identical. The [baseline ledger](../manifests/logging-baseline-preservation.json) lists the exceptions rather than claiming universal byte preservation. No scientific values, target state or licensing scope changes. The original candidate commit and published history are not rewritten; past commits still contain the pre-correction text.

Fourteen focused tests cover plain/quoted/prose forms, literal and multiply escaped newlines/Unicode quotes, adjacent hexadecimal characters, JSONL export, nested JSON integrity, all supported version/variant combinations, exact protocol-type admission, and an independent verifier that rejects a later hidden identity even after allowed matches. All 79 publication tests run in normal and optimized Python. A separate release audit checks the actual known boot value only in memory; the value and its own digest are not published.
