# Export coverage, privacy and reproducibility

The export inventories the complete retained Samsung work tree, not only its latest external-research phase. `research/` preserves substantive authored reports, reviews, annotated instruction excerpts, function maps, protocol analyses, reproducers, experimental source, tests, runbooks, rollback instructions and sanitized scientific observations. Negative and superseded results remain beside later findings.

[The summary](../manifests/export-summary.json) gives exact file/byte counts and workstream coverage. [Source dispositions](../manifests/source-dispositions.json) maps each input to its disposition and original SHA-256. Published records also have a public path and public-byte hash. [The omission index](../manifests/omissions.json) enumerates withheld artifacts with reason, size, hash and an opaque source ID. A source ID is SHA-256 of the original relative filename; withheld filenames are absent so an index cannot expose a private viewing title or credential filename.

Omitted categories include credentials and private access state, local network administration, raw authentication/session/transport envelopes, private media history and photos, whole firmware/vendor binaries, encrypted key blobs, compiled payloads, SDK/runtime/build caches, upstream checkouts that are linked instead, and whole-library mechanical disassembly. Authored function excerpts and their analysis are retained. Private binary inputs can be reacquired independently and verified by hash where lawful and available; they are not recoverable from this repository.

Raw command envelopes are transformed into labeled scientific observations where possible. Payload-staging commands, encoded binary copies, account/network queries and unrelated application log rows are removed. Full VLOG text is reduced to controller/display/HDMI/USB scientific rows. This does not create a byte-identical original, and the manifest records that distinction.

Redactions normalize the researcher's local username, replace RFC1918 addresses with documentation addresses, replace boot/session UUIDs with a sentinel, zero MAC addresses, remove known saved-token values, omit credential-shaped fields, anonymize media labels, and omit long encoded payloads. Protocol UUIDs outside the boot/session UUID pattern remain scientific identifiers. Local absolute evidence roots become `${S95F_EVIDENCE_ROOT}`. This placeholder is explanatory text inside historical code, not a claim that all old scripts support environment configuration.

No symlink is dereferenced into the export. Each is recorded as an omitted reference. The public tree has no executable file bits on retained historical artifacts. Relative layout is preserved and filename privacy rewrites are consistently applied to links and text. References to intentionally withheld inputs can remain; use the disposition manifest and nearby input manifests to understand those dependencies.

The exporter is included in [tools/export_public.py](../tools/export_public.py). Given access to the private evidence snapshot, invoke it with explicit source and destination arguments outside that source tree. Publication tools never infer credentials, connect to a television or run retained experiments. The ongoing source tree can change; snapshot hashes identify the exact bytes exported rather than claiming an atomic capture of an active investigation.

The publication also uses an out-of-tree, mode-0600 private redaction configuration, passed with `--private-redactions`. Its schema is `{"labels": ["private label"], "names": [["private alias", "subject_a"]]}`. The actual labels and alias dictionary are omitted because bundling them would expose the identities being removed. Without that private configuration, the generic exporter cannot reproduce the exact public aliasing or claim to sanitize arbitrary media/account content. The public manifests verify the resulting bytes independently of the private configuration.

The initial release retains a separate post-cutoff outcome report in `manifests/post-cutoff-provenance.json`. Its original manifest, audit facts and cutoff remain pinned at the initial Git commit in [release history](../manifests/release-history.json). The later [evidence update](update-20261028.md) adds completed CA/CB/BZ and firmware acquisition outcomes without overwriting that historical audit or rehabilitating rejected trials.

The current accounting includes 20,418 discovered inputs: 20,414 regular files and 4 undereferenced symlinks. The research subset has 5,738 files (5,219 direct/redacted exports and 519 scientific extractions), 87,368,908 public research bytes, and 14,680 omitted inputs. This includes 152 entries explicitly deferred because authentication/integration/schema work was still in progress. Their bytes were not read, hashed or copied; new work created after enumeration is outside the snapshot. The current enumeration began 2026-10-28T00:19:41.630418+00:00 and export completed 2026-10-28T00:20:53.591401+00:00. This is a per-file research snapshot, not a claimed atomic image of an active workspace.

Files above the existing 8MB public-size limit are classified from a bounded magic prefix and hashed in 1MB chunks, so a multi-gigabyte omitted firmware archive never needs to be loaded into memory. OEM ZIP/MSD files retain acquisition and digest references only.

`fixtures/onset-cb.json` is an explicit exception to generic encoded-payload omission: it contains only 18 bounded, reviewed controller-state windows totaling 2,268 bytes, plus native scientific times/counters and coarse physical/recovery classification. Each original byte window has its own hash and an independent offline decoder. It contains no firmware image, encrypted key blob, authenticated command envelope, account/media data or boot identity. The [fixture verifier](../tools/verify_onset.py) is designed for a fresh public clone; original private-root parser/hash assertions remain historical and are not silently changed to make deployment tools runnable.
