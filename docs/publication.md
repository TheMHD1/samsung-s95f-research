# Export coverage, privacy and reproducibility

The export inventories the complete retained Samsung work tree, not only its latest external-research phase. `research/` preserves substantive authored reports, reviews, annotated instruction excerpts, function maps, protocol analyses, reproducers, experimental source, tests, runbooks, rollback instructions and sanitized scientific observations. Negative and superseded results remain beside later findings.

Exporter policy version `2026-10-28.3` closes a gap discovered before the new firmware work was exported: `private/` is now excluded at **any depth**, including mixed workstreams with authored source beside private plans. Known sensitive plan/configuration basenames are independently denied if moved outside that directory. These path-denied records are not opened or content-hashed for export; their original names, content hashes and individual sizes are absent from public disposition rows. Aggregate omitted byte counts remain available. A known saved token can still be read solely by the existing redactor to remove copies from otherwise eligible historical text; that credential is never an export input or manifest value.

[The summary](../manifests/export-summary.json) gives exact file/byte counts and workstream coverage. [Source dispositions](../manifests/source-dispositions.json) maps each input to its disposition and, where permitted, original SHA-256. Published records also have a public path and public-byte hash. [The omission index](../manifests/omissions.json) enumerates withheld artifacts with reason and an opaque source ID; nonprivate omissions can also retain size and hash. A source ID is SHA-256 of the original relative filename; withheld filenames are absent so an index cannot expose a private viewing title or credential filename. Published older commit-pinned manifests retain their historical policy; this change does not rewrite them.

Omitted categories include credentials and private access state, local network administration, raw authentication/session/transport envelopes, private media history and photos, whole firmware/vendor binaries, encrypted key blobs, compiled payloads, SDK/runtime/build caches, upstream checkouts that are linked instead, and whole-library mechanical disassembly. Authored function excerpts and their analysis are retained. Private binary inputs can be reacquired independently and verified by hash where lawful and available; they are not recoverable from this repository.

The private basename denial includes actual decrypted metadata/section plans, TLS configuration and connection records, listener-port records, raw authenticated header/envelope files, and acquired item key files. Whole decrypted firmware, unpacked filesystems, partition dumps, raw OEM/source acquisition trees, and per-binary `.records` chunk directories are also path-denied regardless of extension or apparent text format. An extensionless kernel or an extracted OEM configuration file is not authored research source. Existing upstream-checkout/license boundaries remain in force; original authored acquisition tools and analysis/tests outside raw acquisition trees remain eligible. Mixed JSON inventories replace private-reference rows with a metadata-omission marker, and nonce/salt/signature-value keys receive defensive redaction. These rules supplement human review; they do not claim to recognize arbitrary secrets under unknown names.

Raw command envelopes are transformed into labeled scientific observations where possible. Payload-staging commands, encoded binary copies, account/network queries and unrelated application log rows are removed. Full VLOG text is reduced to controller/display/HDMI/USB scientific rows. This does not create a byte-identical original, and the manifest records that distinction.

Redactions normalize the researcher's local username, replace RFC1918 addresses with documentation addresses, replace boot/session UUIDs with a sentinel, zero MAC addresses, remove known saved-token values, omit credential-shaped fields, anonymize media labels, and omit long encoded payloads. Protocol UUIDs outside the boot/session UUID pattern remain scientific identifiers. Local absolute evidence roots become `${S95F_EVIDENCE_ROOT}`. This placeholder is explanatory text inside historical code, not a claim that all old scripts support environment configuration.

No symlink is dereferenced into the export. Each is recorded as an omitted reference. The public tree has no executable file bits on retained historical artifacts. Relative layout is preserved and filename privacy rewrites are consistently applied to links and text. References to intentionally withheld inputs can remain; use the disposition manifest and nearby input manifests to understand those dependencies.

The exporter is included in [tools/export_public.py](../tools/export_public.py). Given access to the private evidence snapshot, invoke it with explicit source and destination arguments outside that source tree. Publication tools never infer credentials, connect to a television or run retained experiments. The ongoing source tree can change; snapshot hashes identify the exact bytes exported rather than claiming an atomic capture of an active investigation.

The publication also uses an out-of-tree, mode-0600 private redaction configuration, passed with `--private-redactions`. Its schema is `{"labels": ["private label"], "names": [["private alias", "subject_a"]]}`. The actual labels and alias dictionary are omitted because bundling them would expose the identities being removed. Without that private configuration, the generic exporter cannot reproduce the exact public aliasing or claim to sanitize arbitrary media/account content. The public manifests verify the resulting bytes independently of the private configuration.

The initial release retains a separate post-cutoff outcome report in `manifests/post-cutoff-provenance.json`. Its original manifest, audit facts and cutoff remain pinned at the initial Git commit in [release history](../manifests/release-history.json). The later [evidence update](update-20261028.md) adds completed CA/CB/BZ and firmware acquisition outcomes without overwriting that historical audit or rehabilitating rejected trials.

The current accounting includes 84,574 discovered inputs: 80,991 regular files and 3,583 undereferenced symlinks. The research subset has 6,544 files (5,975 direct/redacted exports and 569 scientific extractions), 93,247,989 public research bytes, and 78,030 omitted inputs. This includes 221 explicitly deferred inputs deferred or outside the sealed source selection; completed DB/DC tools are now included. Nested private filesystem records are independently path-denied. Deferred/private input bytes were not read, hashed or copied for export. Enumeration began 2026-10-28T02:16:35.660736+00:00 and export completed 2026-10-28T02:17:51.183204+00:00. This is a per-file research snapshot, not a claimed atomic image of an active workspace.

Nonprivate files above the existing 8MB public-size limit are classified from a bounded magic prefix and hashed in 1MB chunks, so a multi-gigabyte omitted firmware archive never needs to be loaded into memory. Path-denied private inputs bypass even that prefix read/hash. Official encrypted ZIP/MSD acquisition facts can retain independently authored provenance and digest references; OEM payload bytes are never included.

`fixtures/onset-cb.json` is an explicit exception to generic encoded-payload omission: it contains only 18 bounded, reviewed controller-state windows totaling 2,268 bytes, plus native scientific times/counters and coarse physical/recovery classification. Each original byte window has its own hash and an independent offline decoder. It contains no firmware image, encrypted key blob, authenticated command envelope, account/media data or boot identity. The [fixture verifier](../tools/verify_onset.py) is designed for a fresh public clone; original private-root parser/hash assertions remain historical and are not silently changed to make deployment tools runnable.

The completed filesystem-reader update retains the narrowly named `LICENSE.upstream-MIT` notice beside its original patch and pinned upstream provenance. Upstream source checkouts and raw extracted OEM trees remain excluded; the project license does not replace upstream MIT/GPL terms. The current firmware evidence graph/guide and layered autonomous outcomes are documented in the [evidence update](firmware-evidence-guide-20261028.md).

Version2026-10-28.3 also closes filename-key inventories: private/sensitive mapping entries are removed with only an aggregate omitted-reference count, in addition to the existing path-field metadata omission. This prevents names/sizes/hashes of withheld plans from surviving in mixed deployment manifests. Existing commit-pinned historical snapshots retain their original transform; no actual salt/nonce/signature/token value was found by the preceding release audit. The new release applies the stronger policy consistently across all eligible historical records.

An explicitly deferred editor/build output can disappear after enumeration. That entry remains an opaque in-progress omission with size-unavailable metadata, no content read/hash, and a separate disappeared-entry count. It never becomes a selected input or a false zero-byte file. Stable selected-source hashes are checked independently before publication.

This checkpoint also seals [explicit source selection](../manifests/source-scope.json) by opaque source ID: previously inventoried inputs plus frozen DB/DC/DE/DF/DG/DH files, with DE additions limited to its initial/record/frame inventories. Use `--source-id-allowlist manifests/source-scope.json` with the exporter to prevent future directories from entering the snapshot. The selection digest is recorded in the disposition summary. An unlisted new input is omitted before content read/hash; exact selected original/public hashes remain separately recorded. Volatile-limit source/trials, DE limit-model work and future DM captures are outside this release.
