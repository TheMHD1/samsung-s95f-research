The [CB findings](../research/panel-idle-20261026/overnight/onset-trial-20261028cb/findings.md) and [independent capture review](../research/panel-idle-20261026/overnight/onset-trial-20261028cb/reviews/independent-capture-review.md) establish one accepted synchronized recorder invocation: five full clean cycles, followed by a transition in cycle six. One Left down/up pair ran after the first full clean cycle while the unchanged USB read loop continued with a single USB owner. The global totals are 36 request headers, 36 completed data reads and 72 bulk transfers. Eighteen retained windows preserve the first clean baseline, last clean cycle, transition and post-fault set; older clean cycles are not all retained as raw data.

The latest retained clean R transaction and first faulted R transaction form a conservative software bracket from 167671010145 to 167671260439 target-monotonic microseconds: **250.294 ms**. Both transactions occur after the Left Up call returned. Their independently decoded `(stop, fault, ordinaryGate)` halfwords change from `(0, 0, 1)` to `(1, 0x1001, 0)`. This is a USB observation bracket conditional on reply freshness, not an exact physical-light timestamp or proof that the key caused the fault. The owner separately reported that the panel went dark; the report provides no instantaneous physical timestamp.

The [public scientific fixture](../fixtures/onset-cb.json) contains the exact 18 bounded controller windows and normalized native scientific JSON. The [standalone verifier](../tools/verify_onset.py) checks lengths, hashes, fixed addresses, transfer ordering, independently decoded RT tuples, counter arithmetic and key timing using only Python's standard library. Private authentication/transport records are excluded. The verifier does not reauthenticate the original root session or independently prove the phase premise.
