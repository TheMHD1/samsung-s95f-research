506: ### 8.1 On-device persistence is impossible on this target
507: 
508: We searched specifically for a writable location that is executed at boot. There
509: is none, for four independent reasons.
510: 
511: 1. **The boot hooks live on read-only partitions.** `/` is `vdfs ro` (1.4 G, 100 %
512:    used) and the "product" partition `/prd` is also `vdfs ro` (53 M, 100 % used):
513: 
514:    ```
515:    /dev/root     on /     type vdfs (ro,relatime,posixacl)
516:    /dev/subroot2 on /prd  type vdfs (ro,relatime,posixacl)
517:    /dev/mmcblk0p20 on /mnt/systemrw type vdfs (rw,noatime,posixacl,dncs)
518:    /dev/mmcblk0p21 on /opt        type vdfs (rw,noatime,posixacl,dncs)
519:    ```
520: 
521:    The only writable persistent areas are `/opt` and `/mnt/systemrw`; `/tmp`,
522:    `/run` and `/var/run` are tmpfs.
523: 
524: 2. **systemd has no writable directory on its unit search path.** PID 1 is systemd
525:    244 and reports:
526: 
527:    ```
528:    UnitPath=/etc/systemd/system /run/systemd/system /run/systemd/generator
529:             /usr/lib/systemd/system /prd/usr/lib/systemd/system
530:             /run/systemd/generator.late
531:    ```
532: 
533:    Every entry except the `/run` generators is on a read-only partition. `/opt`
534:    and `/mnt/systemrw` are *not* searched. We proved this by dropping a probe unit
535:    into both `/opt/etc/systemd/` and `/opt/usr/share/systemd/system/` (both
536:    writable), running `systemctl daemon-reload`, and looking for it: `found: 0` in
537:    each case.
538: 
539:    The unit files that *do* watch writable paths (e.g. `tts-download-service.path`,
540:    `vdtizen-bootseq-*.path`) only trigger fixed, signed binaries — none of them
541:    runs a script from a directory we control.
542: 
543: 3. **Unsigned code will not run.** The kernel UEP rejects unsigned native
544:    executables (`[uep][bash] the file is NOT signed!!`), and Tizen refuses to
545:    install an unsigned package. The only unsigned-code primitive we have (managed
546:    code via the signed `/usr/bin/dotnet`) still must be *invoked*, which needs a
547:    boot hook.
548: 
549: 4. **Writable boot state is volatile.** `/run/systemd/system` *is* on the unit
550:    path and writable, but it is tmpfs, so anything placed there is gone after the
551:    next boot by design.
552: 
553: Persistence on this target therefore cannot be "drop a file and forget it"; it
554: must be re-armed from outside the TV after every boot — exactly what upstream
555: does.
