## Root-source claim checks

The report's principal source-level criticisms are supported by actual code:

* **Port mismatch:** manager `BridgePort()` reads the custom file (`Program.cs:746–755`); relay uses default 26103 unless `args[0]` overrides it (`bridge-relay/Program.cs:22–46`); generated service supplies no arguments (`modules/bridge-service/boot.sh:23`).
* **Proof weakness:** fresh-proof and later poll use timestamp checks plus the literal `SELFROOT-PROOF uid=0`, not authenticated four-ID process evidence (`Program.cs:809–823, 1060–1074`). The prefix is more specific than an arbitrary `uid=0` string, but the report's trust distinction is correct. The upstream controller checks an authenticated nonce-bound frame and all four IDs (`root_agent.py:500–514`).
* **Safe-mode order:** the fresh-proof return precedes safe-mode evaluation (`Program.cs:921–953`), so same-boot reopen is not a general undo operation.
* **Impossibility argument is incomplete:** DemonKingSwarn `ROOTING-RESEARCH.md:506–555` enumerates read-only roots, systemd search paths and selected watchers. It does not exhaust writable application/database inputs consumed by existing boot services. That logical gap establishes neither persistence nor incompatibility on S95F.
* **Source delta:** independent Git reads confirm the two local HEADs and modified archive-root/test files exactly as reported. The common C# archive payload is byte-identical to reviewed upstream; actual Python diff shows upstream active-runtime symlink fallback versus the local installed-runtime-directory fallback. A source update must preserve the local adaptation rather than overwrite it. [Hashes/status](audit-artifacts/source-spotchecks.json).

## Firmware result: independently confirmed structure, no decryption claim

The saved prefix independently hashes to `01821f40cf70841649c856090e23b35be6173659fb54be11f3b661a3e37bf92d`. Reinflating the compressed bytes after the **original retained ZIP local header** reproduces it exactly. Parsing the original retained ZIP central-directory tail separately gives the MSD member length 1,493,538,434, matching the nine-interval endpoint. This does not verify the full-member CRC; the ZIP's stored CRC is only a declared value without all member bytes. [Independent MSD results](audit-artifacts/independent-msd.json).

The report's clear descriptor end 234, encrypted header `[234,4290)`, `Salted__` marker at 242, payload IDs 1001–1009, every listed offset/length, contiguity and complete retained metadata block all check out. The EU manifest's first payload is larger by 23,068,672 (`0x1600000`) bytes; the remaining eight lengths match. Candidate target filenames are correctly qualified; matching lengths do not supply target contents, names, salts or CRCs.

The modern source really implements SWU TA command 0 initialization, command 1 update and command 2 finish. The host promotes `.partial` only after CRC equality, while invalid PKCS#7 is passed through. Managed startup launches `BuildReport`, calls SWU probing, and opens `IPAddress.Any:45679`; `ProbeSwu` tries four command-3 unwrap modes. These observations support the report's warning that deploying the full Probe is broader than the narrow streaming-decrypt functions. They do not demonstrate the Canadian target's TA ABI, safe behavior or successful extraction. No retained decrypted artifact was independently tested, and the missing VDFS extractor correction remains a reproducibility gap.
