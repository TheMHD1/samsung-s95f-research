# Independent SWU normal-world ABI audit

2026-10-27 UTC. This ninth independent review reads retained files only. It makes no target connection, TEEC load/call, TA command, deployment, upstream Probe execution, or secret acquisition. Its owned outputs are this report and `reviews/swu-audit-artifacts/`. Other workers' reports were read for context; conclusions below were checked against original ELF bytes with a separately written Capstone/ELF reader.

## Decision

A narrowly scoped direct-TEEC metadata helper is now concrete enough to implement and review offline. The actual installed normal-world client supplies the UUID, byte-packed parameter words, command numbers, buffer layout, and returned-length slots. The critical correction is **60 bytes of operation storage, including a backend word at offset 56**. The 56-byte Python “modern” operation is undersized for this target's installed backend and must not be executed unchanged. Preserve the target's modern partial-memory enums `0x0d/0x0e` while adding that tail; choosing the Python “legacy” profile would also change parameter enums and is not the fix.

Normal-world frame qualification does not establish whether a new helper identity is accepted by the daemon/TA, whether callbacks occur, or whether secure-world state persists. Those are explicit runtime unknowns. They do not prevent writing and checking the bounded helper offline. A later centrally coordinated single-session test can stop on the first failed stage; no command 3, mode enumeration, or updater entry point is required.

## Full operation storage and field layout

All offsets below are ARM32 little-endian offsets. Native pointers and size/count words are 4 bytes. Use natural 4-byte alignment and compile-time size/alignment/offset assertions; do not compile host 64-bit pointer layouts and assume they are target layouts.

| Object/field | Offset / size | Evidence and qualification |
|---|---|---|
| `TEEC_Context` | 4-byte opaque handle | Core passes its object base to InitializeContext. Common `insertContext` stores the mapped handle through that pointer. Treat the word as opaque, not an owned C++ pointer. |
| `TEEC_Session` | 4-byte opaque handle | Core session starts at client+4, with first shared object at +8. Common `insertSession` stores through that public handle pointer. |
| `TEEC_SharedMemory` | 36-byte storage, align 4 | Core allocations at client+8, +44, +80 establish stride36. Backend Allocate accesses buffer+0, size+4, flags+8; common `insertMemory` writes its map token at public object+12 (`0x1e8f6`). Reserve and zero all36 bytes. |
| Shared memory implementation region | `[12,36)` | Only its token at12 is demonstrated on this backend path; the remaining bytes must stay reserved. Do not assign the older Python linked-list/context/identifier semantics to this backend without evidence. |
| `TEEC_Parameter` | 12-byte union, align4 | Common value/memory marshalling uses public parameter stride12. Memory member is parent+0, size+4, offset+8; value member is a+0, b+4. |
| `TEEC_Operation.started` | 0, size4 | Backend Invoke clears the supplied operation's first word; zero it before every call. |
| `paramTypes` | 4, size4 | Common `handleInputArgument` loads `[operation+4]`, shifts by `index*8`, masks `0x7f` at `0x15016..0x1501c`. |
| Four parameters | 8, 20, 32, 44; 12 each | Common handleInputValue reads the two words at `operation+8+12*i`; output handling writes back there. |
| Backend implementation/cancellation word | 56, size4 | Non-null-operation Invoke writes this word. Required storage extends through byte59. |
| Full helper operation | **60 bytes, align4** | This is the concrete declaration required for the reviewed call path. The first56 bytes are the public parameter prefix, not full storage. No debug type information was retained to independently quote a vendor-header `sizeof` declaration. |

The decisive trace is common `teecSession::invokeCommand`: `r7` receives the stack argument `TEEC_Operation*` at `0x208e4`; at `0x209b6` it computes `r7+0x38`; `0x209ba` sends that address in the transport frame; `0x209c0` stores zero to `[r7+0x38]`. The operation wrapper retains the same operation pointer at its own+8 (`0x15160`), which gates this path. This is a direct out-of-bounds write for a standalone56-byte allocation. Common session-open also zeroes `[operation+0x38]` at `0x164a8` when a non-null open operation is supplied. The proposed open operation is null, but all commands0/1/2 supply operations. Backend `TEEC_RequestCancellation` reads this word at `0x5954` and `0x5a18`; omitting cancellation calls does not eliminate the Invoke write. [Independent common disassembly](swu-audit-artifacts/common-independent-disassembly.txt), [backend disassembly](swu-audit-artifacts/backend-independent-disassembly.txt).

Do not reconstruct the proprietary daemon transport in the helper. Use the installed public wrapper and its backend/common stack; the map tokens, internal24-byte transport parameters, cancellation states and socket details belong to that implementation.

## Normal-world command contract

Core imports the required seven TEEC functions with version `TRUSTWARE3.0`. It does not import a TEEC callback-registration function. Open at `0x245594` initializes context, allocates three64KiB shared objects with flags3, and calls OpenSession with public login0, null connection data and null operation. The UUID's original16 bytes at Core VA `0x3fc2e8` decode to `22222221-0000-0000-0000-000000000001`.

| Command | Actual byte-packed `paramTypes` | Verified output/count handling |
|---|---:|---|
| 0, initialization (`0x24581c`) | `0x01010d0d` | p0 encrypted blob partial input; p1 salt partial input; p2/p3 values. Invoke result is checked before initialized state is set. |
| 1, update (`0x245ed8`) | `0x00020e0d` | p0 ciphertext input; p1 output memory; p2 value output. Core reads produced bytes from operation+32, **p2.value.a**, at `0x245f58`. It advertises output size equal to the input chunk length. |
| 2, finalization (`0x245d98`) | `0x0000020e` | p0 output memory, p1 value output. Core reads produced bytes from operation+20, **p1.value.a**, at `0x245df2`. It advertises64KiB output capacity. |

The common library independently confirms eight-bit parameter slots; ordinary GP nibble packing is wrong for these installed calls. `TEEC_MEMREF_PARTIAL_INPUT=13`, output14, input value1, output value2 and NONE0 reproduce all three literal words. The source's default mode/key assumptions must be qualified against the Core caller, not inferred from enum labels alone. Core header decoder at `0x1d614c` constructs the first four-word record `[1,2,1,2]` in order at `0x1d6180..0x1d618a`, followed by a second record. The first record resolves to **p2=(0,1), p3=(1,0x201)**: decrypt0, encrypted-passphrase1, derivation1, mode1 + (key-size2 << 8). The applicability worker independently supplied the full trace; this review then disassembled the original factory/forwarder bytes: header caller `0x1d5088..0x1d50ac` passes record[0]=mode1, record[1]=key-size2, record[2]=derivation1 and fixed crypt-type1; factory `0x243182..0x24318a` converts nonzero crypt-type1 to encrypt0 with CLZ then >>5, forwards these at `0x2431be..0x2431de`; platform `0x244e7c` forwards to constructor `0x246d20`; constructor `0x246e6a..0x246e86` forwards to init; init `0x245918..0x24593c` packs mode + (key-size<<8). No candidate loop belongs in the metadata helper. [Independent Core disassembly](swu-audit-artifacts/core-independent-disassembly.txt).

Selector05 records `isSubmodelKeyType=False`, master and submodel files each416 bytes, and master SHA-256 `d8af420d63b9cb2643783c56ce7396a5fd4d809e48df0bd321781cfd025e8220`. Core `0x244698` is the installed selector consumer. This is sufficient historical selection evidence for pinning the master path in a fixed single-request helper, with pre-call file type/size/hash checks that fail if it changed. No blob contents were acquired or printed in this audit. A library's `isProduction()` result and this separate database selection must not be treated as interchangeable.

## Exact firmware boundary and integrity check

The retained65,494-byte prefix hash is `01821f40cf70841649c856090e23b35be6173659fb54be11f3b661a3e37bf92d`. Independent byte checks find envelope `[234,4290)`, wrapper `[234,242)`, literal `Salted__` `[242,250)`, salt `[250,258)`, and ciphertext `[258,4290)`:4032 bytes,252 AES blocks. Ciphertext SHA-256 is `b7252dbea64d63a7ee9c3b038597dd99ae94a5e531246d53c15e97d274ed9eca`.

The LE word at238 equals `0xefed4e54`, exactly zlib CRC32 of the4032 ciphertext bytes. That is independently reproduced, not borrowed from the EU sample. This checks retained ciphertext and its boundary. It does not authenticate the package, validate plaintext, recover the meaning of the first wrapper word, or replace a bounded plaintext parser. Salt bytes are intentionally omitted from every review output. ## Smallest reviewable next helper

Implement an isolated C executable/library pair or one executable for a single fixed request. Do not carry the full Probe process into it: pinned `Program.cs` starts `BuildReport` automatically at line25, binds all interfaces at line31, and BuildReport enters capture probes and `ProbeSwu`; `ProbeSwu` iterates four command3 unwrap modes. Its native source also relies on an unretained vendor header. Source reuse should be limited to reviewed call-frame ideas, with explicit local ABI declarations and no automatic Probe startup.

Before any target execution, the reviewable deliverable should contain:

1. ARM32 declarations asserting Context4, Session4, SharedMemory36, Parameter12, Operation60, UUID16 and alignment4; explicit offsets through implementation56; literal command words or an eight-bit macro with compile-time assertions. Build against the observed versioned public exports and retain build inputs/hash.
2. A host-only injected-TEEC mock test that writes the operation word at56, mutates output memref sizes, injects excessive produced counts and stage failures, and checks all objects/canaries. This is a meaningful check for the identified ABI and length defects. It must verify exactly0,1,2 once on success and no later command after failure.
3. Fixed input: exact prefix/ciphertext hash,8-byte salt,4032-byte aligned ciphertext,416-byte master blob. Read the blob only in the TV process, verify complete regular-file read plus EOF, never return or log its contents. Zero all storage and allocated buffers. Keep the ciphertext and output outside the blob's buffer until initialization succeeds.
4. One context, three64KiB shared buffers, one public-login session with null open operation, one init, one update and one finalize. Retain64KiB allocation/final advertised capacity to match the installed client; bound published plaintext to4032 aggregate bytes. No retries, selector mutation, command3, mode search, callback registration, listener, arbitrary file route, updater invocation or installation path.
5. Reset result/origin and produced counts for each call. On nonzero result, do not inspect/copy output. On success, bound each returned value count against the original advertised memref capacity, actual shared allocation, and remaining aggregate output capacity using subtraction (`produced <= max-total`), preventing addition overflow. Never substitute a returned memref.size for the value count or trust an output-mutated size as the original capacity.
6. Track successful initialization/allocation/session stages explicitly; close the session once, release only successfully allocated objects in reverse order, and finalize only an initialized context. Capture the first failure without replacing it with cleanup diagnostics. Close/release is cleanup, not demonstrated secure-world rollback. Avoid extra command2 after an update failure merely to “reset” unknown TA state.
7. Keep plaintext private until the one session completes, strict PKCS#7 handling is qualified, and bounded header parsing reconciles IDs/offsets/sizes with this target's clear directory. Do not require a guessed plaintext CRC, apply payload CRCs to the header, accept invalid padding unchanged, or claim signature verification. Report only stage/result/origin/counts plus validated metadata.

The first-record command0 values are now statically qualified. The remaining implementation review gap is the actual helper plus ABI assertions and mock results. Daemon identity/access policy, callback behavior, timeout/hang behavior and TA persistent effects remain runtime unknowns to disclose for a later bounded test, not reasons to revert to the broad upstream Probe.


## Follow-up: actual isolated source prototype review

The implementation in `sources/minimal-swu-helper/` has now been independently reviewed, beyond the earlier design-only review. **No material state-machine, ABI, output-length or cleanup defect was found in this source prototype.** This conclusion applies to the hashed inputs in [independent-prototype-results.json](swu-audit-artifacts/prototype-review/independent-prototype-results.json), not a future live adapter. The prototype has no main routine, target loader, TEEC imports, file reader, network route, cryptographic binding or metadata parser. Its supplied API is an injection boundary; the only executable built or run in this review was a host mock. A separately compiled optimized prototype object has only `__stack_chk_fail` undefined, confirming no direct TEEC/dlopen/socket binding in that object.

The actual header asserts Context4, Session4, SharedMemory36, Parameter12, Operation60 and UUID16 with4-byte alignment, parameter offsets8/20/32/44 and backend tail56. The operation is fully reset before each command. Mock Invoke writes through offset56, mutates started, and requires a fresh zeroed operation on the next command. Golden frames independently match all15 little-endian words for each of commands0/1/2, including p2=(0,1), p3=(1,0x201), update4032 and final65536 capacities. The target public export adapter remains intentionally absent; these fixed-width address words cannot be forwarded as ordinary host64-bit pointers.

The implemented success path contains exactly one init, one update and one final command, with no fallback/retry/command3. Each failed result exits before reading its output counts; no cleanup command2 is issued after a failed update. The implementation takes counts from p2.value.a and p1.value.a and compares them against fixed original capacities and remaining4032-byte aggregate space, never an output-mutated memref.size. The latter is deliberately set to0 and UINT32_MAX by the mock in separate successful scenarios. Excess update4033, final17 after update4016, and final65537 are rejected without copying the bad count. Subtraction-based aggregate checks avoid addition overflow.

Allocation count increments immediately after successful allocation, before map/address validation, so a subsequent local validation failure still releases that allocation. Only successfully initialized context/session stages are finalized/closed; shared objects release in reverse order. Cached backing views are wiped before release, source blob is wiped on all paths where its declared size is416, and private plaintext and operation storage are wiped at exit. If initial mapping is unavailable, the code releases that allocation without dereferencing an invalid view; this occurs before any blob/ciphertext copy. It preserves the first failure diagnostics. A completed sequence reports `SWU_QUARANTINED`, keeps `metadata_published=0`, returns no plaintext, and wipes private output. Thus success means simulated command completion, not validated metadata or a completed firmware decode.

Independent validation used a fresh strict C11 build with `-Wall -Wextra -Wpedantic -Werror`, AddressSanitizer and UndefinedBehaviorSanitizer, with outputs entirely in this review's own subdirectory. The author's suite passed:3 golden frames,8 failed TEEC stages,2 output-size mutation successes,3 count overflows and2 public input rejections. This reviewer added [12 fault cases](swu-audit-artifacts/prototype-review/independent_faults.c): returned allocation size corruption, null buffer, failed map and failed address conversion at each of the three allocation positions. All passed; no command ran on those paths, release counts/order were exact, and the caller's blob was wiped. [Combined test log](swu-audit-artifacts/prototype-review/independent-faults.log).

The finalized offline validator was independently run under normal Python and `-O`, using this review's own rebuilt host executable. Outputs are byte-identical (SHA-256 `d485b9ca5079dc1313ef7f8b18d89d75c5c7bb3d60171b757f65554847e4f6a0`); all16 malformed prefix variants are rejected, exact envelope/cipher hashes and all five ELF hashes match. [Normal validation](swu-audit-artifacts/prototype-review/normal-validation.json), [optimized validation](swu-audit-artifacts/prototype-review/optimized-validation.json). Hash checks in the public C entry are exercised only as rejection cases because the encrypted blob was not acquired. Successful sequencing tests explicitly enter the static validated core with synthetic bytes; they are not proof of the absent SHA implementation or live blob reader.

This source prototype is suitable for the next centrally coordinated implementation stage. Before a live decode, the concrete missing pieces remain: a reviewed ARM32 adapter for the installed versioned TEEC exports, actual SHA-256 and address/map implementations, target-side complete regular-file/EOF/identity checks, selection-drift handling, and qualified plaintext/padding/schema/integrity validation or a retained quarantine design. None requires asking the user to repeat existing authorization. Actual daemon/helper identity acceptance, callback/hang behavior and secure-world persistent effects still cannot be established by host mocks. The reviewed prototype was not deployed or connected to the TV.
