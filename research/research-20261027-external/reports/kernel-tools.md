## Concrete new result: both syscall ABIs are stubbed in the saved kernel

**The matching stored ARM64 Image routes native and compat BPF/perf calls to unconditional `-38` return stubs.** This closes the proposed native-ABI escape hatch for this *stored build*, without another denied helper launch. The previous successful ARM32 CLR observation remains the only live syscall result; the executing kernel text has not been hashed. Therefore this is stronger than “compat returned ENOSYS,” but does not establish that every possible running/native kernel interface is globally unavailable.

The input is the retained Linux 5.4.261 Image, SHA-256 `77b6070c12a53f2b7ede3b7c503e242759e22dbaef2d12cc91b556416fed455d`. Its existing matching banner/slot/CRC provenance remains qualified by the original [kernel manifest](../../panel-idle-20261026/overnight/kernel-image-manifest.json). The artificial export ELF is unnecessary for the following check; it is neither original vmlinux nor live address evidence.

| ABI / normal table at Image offset | syscall number | table entry offset | handler offset | exact body |
| --- | ---: | ---: | ---: | --- |
| AArch64 / `0x7f07e0` | perf `241` | `0x7f0f68` | `0x52388` | `a0048092 c0035fd6` |
| AArch64 / `0x7f07e0` | BPF `280` | `0x7f10a0` | `0x52430` | same |
| AArch32 compat / `0x7f5028` | perf `364` | `0x7f5b88` | `0x52388` | same |
| AArch32 compat / `0x7f5028` | BPF `386` | `0x7f5c38` | `0x52430` | same |

These are `mov x0,#-38; ret`, without argument reads, map creation or event allocation. The table identification is supported by dispatch code, beyond pointer-array shape:

- Native caller instructions at `0x19050` / `0x1909c` load syscall number from saved `x8`; their ADRP/ADD pairs at `0x19054/58` and `0x190a0/a4` construct `0x7f07e0`.
- Compat caller `0x190e0` loads saved `x7`; `0x190d4/d8` constructs `0x7f5028`.
- All three BLs enter `0x18ec8`; `0x18ee0` retains the supplied table in `x21`, `0x18f08` bounds the number to `437`, and `0x18f28/2c` load `[x21 + number*8]` and branch through it. The vendor bound is **438 entries**, versus upstream 5.4.261's 436; no whole-source identity is assumed.
- Native/compat getpid `172/20`, exit `93/1`, and write `64/4` resolve to the same respective handlers, independently corroborating numbering. All 438 table pointers map inside the saved Image under the consistent stored link coordinate base `0xffffffc010080000`; this is **not a live base**.

The Linux 5.4.261 reference at commit `ef379773e2e76d6470a907ae36c3d12f65a6ecdb` explains the saved-register/table distinction in [syscall.c L157–168](https://github.com/gregkh/linux/blob/ef379773e2e76d6470a907ae36c3d12f65a6ecdb/arch/arm64/kernel/syscall.c#L157), the native/compat tables in [sys.c L51](https://github.com/gregkh/linux/blob/ef379773e2e76d6470a907ae36c3d12f65a6ecdb/arch/arm64/kernel/sys.c#L51) / [sys32.c L125](https://github.com/gregkh/linux/blob/ef379773e2e76d6470a907ae36c3d12f65a6ecdb/arch/arm64/kernel/sys32.c#L125), and the numbers in [generic unistd.h L690](https://github.com/gregkh/linux/blob/ef379773e2e76d6470a907ae36c3d12f65a6ecdb/include/uapi/asm-generic/unistd.h#L690) / [compat unistd32.h L741](https://github.com/gregkh/linux/blob/ef379773e2e76d6470a907ae36c3d12f65a6ecdb/arch/arm64/include/asm/unistd32.h#L741). The **local bytes**, rather than those reference definitions, prove the handlers' bodies.

The host-only [verifier](../sources/kernel-tools/verify-syscall-dispatch.py) hash-gates the whole Image, checks those instructions/targets and ABI anchors, and uses explicit exceptions. Normal and `python3 -O` runs produce identical [results](../sources/kernel-tools/syscall-dispatch-result.json). [Dispatch disassembly](../sources/kernel-tools/dispatch.disasm) and [stub disassembly](../sources/kernel-tools/syscall-stubs.disasm) are retained. A direct `IKCFG_ST` scan also returned absent in this uncompressed Image; this does not reconstruct a config or prove every option disabled. The source [extract-ikconfig](https://github.com/gregkh/linux/blob/ef379773e2e76d6470a907ae36c3d12f65a6ecdb/scripts/extract-ikconfig#L14) supplies that marker contract.

**Consequence:** BCC, bpftrace, perf-based probes and BPF-powered tools do not bridge this build's gap merely by compiling for AArch64. Classic socket BPF and internal kernel routines are separate and remain compatible with this finding. No native helper retry, execution-policy change or custom module follows from this result.

Be precise about “read-only”: upstream 5.4.261 documents that reading `trace` temporarily disables tracing while open, and `trace_pipe` consumes records. This research supplies no alternate collector equivalent to the previously rejected low-level recorder.

## Module and analysis compatibility: concrete limits

New offline `readelf` output confirms retained `qdf_tcon.ko` is **ELF64 little-endian AArch64 relocatable**, not ARM32, with build ID `ae35362dde61127ad6c9d85292b612fd978a02f6` and exact vermagic **`13781815, release SMP preempt mod_unload aarch64`**. [Metadata](../sources/kernel-tools/qdf-module-metadata.txt), [modinfo/debuglink](../sources/kernel-tools/qdf-module-modinfo.txt) and input hash [manifest](../sources/kernel-tools/local-evidence-manifest.json) are retained. The module has no `__versions` section in its saved section table; that alone is not proof of the running kernel's config. Its `.gnu_debuglink` names `qdf_tcon.ko.debug`, which was not found among retained files. Any future debug-file candidate needs matching build ID/debuglink CRC before use.

This makes “build a Linux 5.4.261 ARM module” an inadequate plan. Upstream [external-module documentation L57–70](https://github.com/gregkh/linux/blob/ef379773e2e76d6470a907ae36c3d12f65a6ecdb/Documentation/kbuild/modules.rst#L57) requires matching build configuration/headers and, when applicable, Module.symvers. [vermagic.h L37](https://github.com/gregkh/linux/blob/ef379773e2e76d6470a907ae36c3d12f65a6ecdb/include/linux/vermagic.h#L37) and [module.c L3268](https://github.com/gregkh/linux/blob/ef379773e2e76d6470a907ae36c3d12f65a6ecdb/kernel/module.c#L3268) show version checking; signature policy and Samsung checks are additional unknowns. Kernel modules use kernel architecture; an ARM32 managed process does not imply an ARM32 module ABI. No module build/load or bypass experiment is qualified here.

The existing host objdump and a small checked decoder answered the concrete syscall question; installing Ghidra/radare2 adds no missing runtime capability. For subsequent offline data-flow work, preserve distinctions already present in the evidence: raw ARM64 Image/export artificial VAs, relocatable AArch64 module with section-relative relocations, and separate Thumb controller images. A decompiler's guessed types, base or inferred stores cannot classify the external selector-1 code view as writable backing. The [code-write readiness gap](../../panel-idle-20261026/overnight/code-write-readiness-20261027r/code-write-readiness.md) remains unchanged.
