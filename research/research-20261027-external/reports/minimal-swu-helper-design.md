# Fixed metadata-only SWU helper: offline source prototype

2026-10-27 UTC. **Source prototype built, host-tested and independently reviewed; not ready for deployment or target execution.** This work created an isolated C prototype, fixed input manifest, explicit ARM32 storage declarations, and host-only validators. It made no TV connection, library load, TEEC/TA call, deployment, updater/Probe execution, plaintext-key acquisition, firmware change, or flash operation. Writes are confined to this report and `sources/minimal-swu-helper/`; the existing managed TCON helper was not changed.

The purpose is a narrowly bounded acquisition step toward identifying target firmware metadata. It does not establish a cause or repair for the TV blackouts.

## What is ready

The [independent ABI review](../reviews/swu-independent-review.md) and [target applicability report](swu-target-applicability.md) now establish the exact normal-world frame contract. The [prototype header](../sources/minimal-swu-helper/swu_prototype.h) declares Context 4, Session 4, SharedMemory 36, Parameter 12, UUID 16 and **Operation 60 with the cancellation word at offset 56**. Compile-time assertions check sizes, four-byte alignment, parameter strides, and field offsets. Shared memory's implementation bytes `[12,36)` stay opaque; only the token at12 is known. Every operation is fully cleared, including bytes 56–59. The helper preserves modern partial-memory enums 13/14 and eight-bit parameter slots; it does not select a generic legacy profile merely to obtain 60 bytes.

The [source prototype](../sources/minimal-swu-helper/swu_prototype.c) accepts only one exact 4,056-byte metadata envelope and one 416-byte encrypted items blob. The [manifest](../sources/minimal-swu-helper/input-manifest.json) pins envelope SHA-256 `6da1e2386f0f97a180984f249febaf831febfee1adb35a8cefa96f89ad069e0d`, binding wrapper, marker, salt and ciphertext together. The envelope is the retained prefix interval `[234,4290)`; its salt is `[250,258)` and ciphertext `[258,4290)`, exactly 4,032 bytes. The separately checked ciphertext CRC is `0xefed4e54`. Salt bytes are not logged or reproduced in artifacts.

[Selector 05](../target-swu-selector-05/metadata.txt) records `False`, selecting `/usr/share/org.tizen.tv.swu/itemsAESPassphraseEncrypted.txt`, 416 bytes, SHA-256 `d8af420d63b9cb2643783c56ce7396a5fd4d809e48df0bd321781cfd025e8220`. The prototype pins that digest and requires the encrypted blob to remain process-local. This work did not acquire its contents. This is historical selector evidence; a future execution preflight must fail closed if the selected input or its provenance changed.

The fixed lifecycle follows installed Core: initialize context; allocate three 65,536-byte shared objects with flags 3; open UUID `22222221-0000-0000-0000-000000000001` with login 0 and null connection/open-operation pointers; invoke the following sequence once; close, wipe and release allocations in reverse order, then finalize context. Buffer roles are input/blob, output and salt. Ciphertext replaces the blob only after initialization succeeds.

| Command | Byte-packed types | Fixed parameters and output bounds |
|---|---|---|
| 0 | `0x01010d0d` | p0 encrypted 416-byte items blob; p1 eight-byte salt; p2=`(0,1)`; p3=`(1,0x201)` |
| 1 | `0x00020e0d` | 4,032 ciphertext bytes; original advertised output capacity 4,032; count from **p2.value.a** |
| 2 | `0x0000020e` | Original advertised output capacity 65,536; count from **p1.value.a**; remaining aggregate capacity at most 4,032 |

Every returned count is bounded against the **original** advertised capacity, actual allocation and `4032 - total`. Callee-mutated memref sizes cannot enlarge those limits. A nonzero TEEC result stops the sequence before any output count/data is inspected. Diagnostics separate local validation failure from TEEC result and origin; observed invalid counts may be recorded as numbers, never used to copy. No fallback, retry, command3, callback registration, listener, arbitrary command/file route, updater object or payload operation exists.

Normal cleanup tracks successful context/allocation/session stages, preserves the first failure, closes once and releases only successfully allocated objects. Shared buffers, operation storage, private plaintext and the borrowed 416-byte encrypted input are wiped. No final TA command is added after an earlier failure. These cleanup actions do not demonstrate secure-world rollback or guarantee cleanup after a hang, forced termination or crash.

## Host validation completed

Run `make check` in [the source directory](../sources/minimal-swu-helper/). The build uses C11, warnings as errors, AddressSanitizer and UndefinedBehaviorSanitizer. It compiles and executes a host mock only: the prototype has no `main`, installed-library adapter, TEEC import or loader. The test executable has no route to the TV.

- Three independently enumerated 60-byte golden frames match the builders, including synthetic parent addresses and a zero cancellation tail. Canaries cover operation/frame and shared-buffer boundaries.
- The injected backend writes operation+56, changes `started`, poisons failure counts, and changes output memref sizes to zero or `UINT32_MAX`. Valid counts still obey the original capacities. All eight failure stages stop at the expected stage with no later command.
- Two size-mutation success scenarios and three count-overflow scenarios verify exact command budgets, aggregate 4,032-byte bounds, ignored failed-call output, input erasure and reverse cleanup.
- The host-only [input/layout validator](../sources/minimal-swu-helper/offline_validate.py) verifies all five retained target ELF hashes/ELF32 little-endian identities, target directory boundaries, envelope/prefix/ciphertext hashes and ciphertext CRC. It rejects 16 malformed variants, including salt, wrapper, ciphertext, label, interval and truncation changes. Normal and optimized Python produce identical results.

[Retained validation](../sources/minimal-swu-helper/validation.normal.json), [optimized validation](../sources/minimal-swu-helper/validation.optimized.json), [build/test log](../sources/minimal-swu-helper/host-check.log), and [artifact inventory](../sources/minimal-swu-helper/source-inventory.json) make this reviewable. Mock lifecycle success is tested through a private white-box core using synthetic inputs; **it does not prove that the public entry point accepted the real encrypted blob, that SHA-256 target bindings exist, or that a TA accepted a request**. The real envelope is checked independently with host `hashlib`. No host copy of the selected encrypted blob was needed.

The [independent follow-up review](../reviews/swu-independent-review.md) subsequently reviewed the actual hashed prototype and found no material ABI, state, count or cleanup defect. It independently rebuilt and reran the sanitizer suite and added 12 fault cases: corrupted returned allocation size, null buffer, failed mapping and failed address conversion at each allocation position. All stopped before any command and released exactly the successful allocations in reverse order. [Independent results and source hashes](../reviews/swu-audit-artifacts/prototype-review/independent-prototype-results.json), [independent fault log](../reviews/swu-audit-artifacts/prototype-review/independent-faults.log). These results qualify this source prototype, not a future live adapter.

## Exact remaining work

1. **Carry the reviewed boundary into the next implementation.** The ninth independent review and its follow-up now cover the ABI and this actual source. No live runner was created. Any later adapter, file reader or parser changes need their own review and tests; the present pass cannot cover code that does not yet exist.
2. **Supply the target adapter and ordinary-file preflight.** The injected seven TEEC methods must map to the installed `TRUSTWARE3.0` exports, using the declared storage and ARM32 calling convention. `addr32` must reject unrepresentable addresses and `map` must validate the actual owned allocation. The SHA-256 callback needs an independently checked target implementation; no guessed libcrypto ABI is supplied. Read only the fixed envelope and selected fixed blob path with `O_RDONLY|O_CLOEXEC|O_NOFOLLOW`, require regular files and exact sizes, read completely with EOF and unchanged identity checks, and fail on a changed selected-input provenance. Never copy the encrypted blob to the host or log its contents. These adapters/readers are intentionally absent, not hidden deployment code.
3. **Qualify plaintext handling offline first.** The prototype completes only to `SWU_QUARANTINED`, always reports `metadata_published=0`, and wipes all decoded bytes. It deliberately contains no guessed PKCS#7 stripping or OUIT parser. Map exact target padding behavior, first-wrapper-word/plaintext CRC coverage, RSA/trailer semantics and bounded OUIT schema from the retained Core. Then implement and malformed-test strict applicable padding, record limits, duplicate/overflow rejection, and reconciliation with clear IDs 1001..1009 and this target's offsets/sizes. Publish only validated metadata fields; never raw plaintext, passphrases or keys. A return value 0 currently means the bounded mock/TEEC sequence completed to quarantine, **not** that metadata was authenticated or recovered.
4. **Bound a later process invocation separately.** Actual daemon/helper authorization, callback behavior, transport timeout/hang handling, TA persistent effects and crash recovery remain unobserved. A finite outer deadline cannot promise rollback, and forcibly stopping a process cannot promise ordinary cleanup. Retain build/compiler/runtime identity and review the final ARM32 adapter/binary before considering any single-session test. No runtime experiment or automatic retry is part of this deliverable.

The next useful step is the remaining offline plaintext-schema work and a centrally coordinated target-adapter implementation. This prototype does not qualify deployment, firmware application, controller writing, or a permanent blackout fix.
