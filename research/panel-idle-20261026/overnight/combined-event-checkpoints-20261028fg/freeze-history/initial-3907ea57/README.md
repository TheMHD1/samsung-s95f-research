# Combined stock event logger and RTP checkpoints: host prototype FG

This is a new, host-qualified implementation family, not a completed TV experiment. It combines the ET stock logger gate/ring plan with the ER40 eight-window, 58-byte checkpoint reader on one claimed file descriptor. No TV, root transport, network, USB or MMIO operation was performed while building or testing it. The gate payload is a volatile logger write; this is **not a read-only native helper**. The threshold remains 40 throughout. No instruction patch, scratch logger, flash, boot, reset, or generic address/value interface is provided.

The native command has only the fixed `--execute --device N` instance binding inherited from DQ/ER. Four context/profile checks constrain the logger writes: known RT tuple at limit40; exact logger halfword0 before arm and1 before restore; source-qualified R alternative-gate/configuration values; and separately read M/C root10000, mode1 AA0/AC2, and fixed geometry/category/selector. Prearm and the first complete armed clean baseline require scan1. Later observation and fresh cleanup admit only the source-qualified finite scan domain0/1, including a lagged value. Fresh M/C is required both before arm and before restore. The final prerestore R is adjacent to the write, but concurrent stock upper-bit changes after that read are not excluded. These sequential reads are not atomic and do not prove the context remained unchanged after sampling. Any unexpected upper logger bit or invalid fresh context refuses a restore write. Restoration is only an observed readback, not a guarantee against later stock rearming. A captured gate already0 is a separate no-write outcome, not evidence that this process restored it. Source provenance is ET plus inherited DQ binding/ER read/key machinery, pinned in input-pins.json. `qualify-scan.py` pins selected image1 c250: it stores1 atCPU200004d8 if its own sampled stop==0 and ordinarygate==1, else stores0. This updater is asynchronous with host R/M samples; no synchronous R-to-scan equality is asserted. Actual hash-bound FE baseline scan1 and postfault scan0 are tested, with root/category/profile unchanged. Value2 is refused. Initial scan0 still refuses before arming.

## Cooperative operation budget

`budget.json` is the machine-readable contract. Every bulk retains its existing 2000ms USB timeout. A header/data pair therefore reserves 4s. Accepted read headers always get their one matching IN; accepted logger headers always get their one matching 2-byte OUT payload even after clock failure. Short/exceptional transfers enter Unknown; no new header follows. A clock failure before a new header prevents that header, and a clock failure during a completed pair prevents further headers, including a blind restore.

Control pairs, in order:

1. full baseline ring, prearm R, prearm M, prearm C;
2. fixed arm header + 0100 payload, armed R readback;
3. zero or more optional checkpoint pairs, arranged as R/M/C/P/N/H/L/R;
4. fresh prerestore M and C, then R immediately before the write; fixed restore header + 0000 payload when the captured halfword is exactly1; restored R; full post ring.

That is **12 control pairs / 24 bulks**, plus each completed eight-read cycle. If the fresh gate is already0, the restore pair is omitted and reported distinctly. This deliberately strengthens ET's original eight-extra-pair proposal by adding fresh prearm and prerestore M/C. Its full worst-case control duration is48s, so it cannot simply be run unconditionally within the unchanged foreground budget.

The whole cooperative native budget is40s, beginning before cached USB preflight. Before arm, remaining time must cover arm4s + armedR4s + at least one optional pair4s + cleanup26s =38s; slow prearm refuses before writing. The inherited ReadPair also applies the optional admission cutoff to its own fresh pre-header timestamp, so an intervening scheduler/clock delay cannot bypass the check. Before **every** optional pair, admission requires4s + six cleanup pairs24s +2s explicit margin +7s key join reserve =37s remaining. This conservative rule can stop a cycle part way through at ReadyForHeader. Such an observation remains incomplete; no Left is dispatched until all eight reads of the first armed clean cycle complete and their context passes. Cleanup itself rechecks remaining24s plus7s when a key was dispatched. The fixed 2s observation duration, 25ms nominal sleep and56-row cap are retained; period is not guaranteed sample spacing. Fault and Quiescent states are retained distinctly and do not by themselves block valid logger cleanup.

The one Left worker is the inherited bounded implementation, including its release attempt and7s join. Its time is explicitly reserved; it is joined after USB release/close. A native/blocking syscall, stopped scheduler, broken clock, process death or host transport timeout can defeat cooperative timing and restoration. Root45s and host75s are unchanged. Root preamble/serialization delay is outside the native stopwatch; this is not a guaranteed hard deadline or a safety rollback mechanism.

## Evidence retained and interpretation

The compact semantic receipt contains up to56 unchanged58-byte rows, full first armed baseline, last complete set, current possibly partial set, exact logger-control transfers and fresh R/M/C bytes. Ring data goes to `baseline-ring.bin` and `post-ring.bin`, each at most15372B, with exact size and SHA256 in the receipt. Cursor values0..15360 are valid inclusive. No ring index/data is cleared. Baseline and post may wrap or have concurrent readers; neither event freshness nor a no-wrap interval is inferred from a cursor. Event736 is a stock logger argument, not an executing PC, LR, selected-A proof or actual floating-point comparator operand.

All raw capture/checkpoint/control storage and fixed payload arrays are allocated before USB preflight; no new capture is allocated while armed. The inherited runtime pinning/key-thread operations can still fail, so no out-of-memory recovery guarantee is claimed. Output files are acquired exclusively, mode0600, in a private0700 fixed-prefix stage before USB open. JSON goes to its exclusive file, separate from native GC stdout. Ring sidecars are fetched separately using fixed ordinary-file commands only after a valid receipt reports known ReadyForHeader and released/closed ownership. Each fetch is framed, bounded and bound to the receipt hash/size. Unknown phase or malformed receipt causes no further root request. A native refusal is preserved; it is not promoted to successful observation after file retrieval. Only accepted, restored, sidecar-bound results can pass final census, exact inventory/hash checks and removal of the exact11 stage files. Any ambiguity retains the stage and does not retry. No deployment was performed.

The wrapper reuses **byte-identical FC wake-check.py** after staging and the compact zero-I/O smoke receipt, before native invocation. It submits one fixed ordinary VOLUP down/up and bounded cached Apps/noSaver/CSFS checks. Those cached facts and native Left receipts do not prove UI consumption, focus, destination, physical panel state or causation. All physical assertions remain false/unobserved. FG's logger changes are an instrumentation perturbation and require their own future controlled trial, not FC's old completed-capture admission.

## Host reproducibility and scope

Run `sh build-host.sh`, `python3 -B verify-source.py`, and `python3 -B test-host.py` (also `python3 -O -B test-host.py`). Build uses the retained local .NET6 SDK and an empty NuGet source list; task-local SDK, package and temporary directories avoid shared output and disk pressure. `finalize.py` updates derived host checkpoint/manifest/inventory only during authoring; frozen hashes are not to be regenerated during independent review. There is no automatic target execution from any build/test command. Wrapper CLI is dry by default and requires a separately reviewed matching manifest and family-specific readiness to load the existing authenticated/serialized root adapter.

`verify-source.py` proves the inherited read pair body, fixed window map, IOps interface, 58-byte packing, entire binding/claim/release/close prefix, OneLeft prefix, and FC wake helper. Native Bulk changes are limited to the exact fixed ring read and logger header/payload whitelist. Engine scheduling, budget admission, write-pair completion, retention, compact receipt and sidecar publication are new code and need independent review. Tests cover fixed40 drift, failure/short/exception at every transport position, pending-IN/payload completion on late clock errors, slow prearm/no write, incomplete first cycle/no Left, fault/Quiescent cleanup, logger upper-bit refusal, semantic mutations, sidecar corruption and mocked wrapper command ordering/cleanup. Transport/source tests do not establish live bus reachability of every new operation or real logger event production.
