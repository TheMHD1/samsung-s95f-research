# Fixed SWU inline background job lifetime contract (CV)

This is a host-only lifetime library for one fixed, separately reviewed .NET section helper. It has no execute CLI, no staging, no TLS implementation and no target action on import. Tests do not contact a TV or root controller. The implementation does not modify the existing access client, persistent daemon, target root agent, TEEC frames or streaming engine.

## Why a background job

The existing access CLI and persistent daemon each reject foreground execution above 120 seconds. Increasing a host timeout alone cannot bypass that limit. A 1.455 GB section can require a longer lifetime. CV submits one short launch command, detaches a fixed helper with all inherited standard handles redirected, and observes it through short authenticated persistent-root requests. Bulk plaintext continues through the separately reviewed private TLS channel, never the root response frame.

## Public API and composition

`Payload(name,size,sha256)` and immutable `JobSpec(stage,dll,boot,dotnet_sha256,payloads,native_seconds,supervisor_seconds,host_seconds,io_seconds)` describe exact inputs. Stage names follow `/tmp/swu-stream-20261028xx`; the entry point is always `SwuStreamTarget.dll` without arguments. There is no shell command or executable field. The caller supplies the frozen full deployment payload pins and verifies all declared timeouts against the target source/configuration. CV does not infer native alarm configuration from a DLL.

`guarded_access(pinned_access_path)` is an explicit live context manager, to be used only by a centrally coordinated adapter. It hashes the exact existing access source before loading those same bytes, holds its existing global flock for the entire context, checks the original firewall, route, public model/developer host, ready persistent channel, root identity and build, and yields `Access`. Every `Access.exec(fixed_command)` uses the imported `persistent_request` once with a ten-second remote timeout and a 25-second socket timeout. It rejects non-root, timeout, nonzero-exit, stderr, malformed and oversized responses. No bootstrap/acquisition or alternate root path is supplied. Direct same-UID daemon clients remain subject to central coordination.

Within that same context, a controller may pin/recheck staged payloads and start its TLS listener, call `run(access,spec,private_empty_evidence_dir)`, collect native status, validate the separate TLS artifact, and only then clean up. `run` requires the held-lock capability. It persists a private exclusive launch intent before one dispatch; no ambiguous launch is replayed. The evidence directory must be empty, owned by the current user, non-symlink and mode 0700. Intent/terminal/reconciliation records use exclusive no-follow mode-0600 creation and fsync.

Builders `launch_command`, `status_command`, `stop_command`, `collect_command` and `cleanup_command` are exposed for review and composition. They accept only the validated immutable spec. For the frozen five-file CR-shaped deployment the launch is 7,645 bytes, below the existing 8,192-byte command limit. Syntax checks use the actual generated scripts. The `run` method records only bounded status metadata; callers should log each fixed root request/response privately through a wrapper if full authenticated transport provenance is required.

## Target supervisor and exact ownership

Launch verifies stage root ownership/mode 0700, exact payload files (regular, non-symlink, single link, mode 0600, exact size/hash), boot and `/usr/bin/dotnet` hash. Atomic creation of `cm-job` prevents a duplicate launch. Generated scripts and a plan digest are written privately there. `setsid` availability is checked before dispatch. The root shell redirects stdin/stdout/stderr before launching the detached supervisor, allowing the root request to finish without a descendant retaining its capture pipes.

The supervisor and fixed child each acquire their own session/process group. Each reads its own kernel start time and requires PID=PGID=SID. The child publishes its identity, then waits for a bounded go marker before executing dotnet. The supervisor verifies that published PID is its exact child and that boot/start/group/session still match before allowing execution. It polls that same identity using kernel uptime. A deadline kill targets only that verified child group. A PID mismatch, unreadable live proc record, malformed identity or unexpected group never authorizes a kill.

`proc_identity` suppresses the expected cat diagnostic from a disappearing proc stat file. It classifies absence only when the process directory is absent and `/proc/self/stat` remains readable. Other read/parse errors abort. This is an operational classification under a healthy mounted root procfs, not universal proof that an arbitrary process or descendant has terminated. Ordinary exit polling distinguishes this absence from unavailable evidence. The status reader also rechecks the atomically committed exit receipt if the initial receipt test preceded supervisor disappearance; it does not turn a normal exit race into a failed root response.

The supervisor commits a private atomic exit receipt with the immutable job digest, native exit code, deadline flag and direct-child termination classification. The child has no subprocess API in the reviewed helper. A future helper that can spawn descendants requires its own descendant-quiescence review; CV does not infer that all descendants have died merely because a group leader disappears.

## Bounds and failure behavior

Native alarm must be enabled before native/I/O work and be at most 1,700 seconds; the separate channel must have its own total and per-I/O limits (per-I/O at most ten seconds). Supervisor lifetime is at most 1,750 seconds, with at least ten seconds beyond the declared native alarm. Host policy is at most 1,800 seconds and reserves 50 seconds beyond the supervisor for one final bounded status request and one conditional stop. These are bounded process-level attempts. Kernel uninterruptible I/O or a broken lower transport is not made interruptible by this library.

If the supervisor deadline expires, it sends SIGKILL to the bound child group, waits a bounded observation interval and avoids an unbounded `wait` on a still-live task. Unconfirmed termination is explicit and never accepted. Host deadline sends one conditional stop request; this is not a native retry. Missing replies, unexpected frames and interruption produce a reconciliation-required record and retain the job. No new run is attempted. If the host disappears, the remote supervisor and native alarm remain responsible for bounded termination attempts. Releasing a host lock after failure is not permission for concurrent vendor work: the central controller must first reconcile retained state.

`transport_completed` requires confirmed child termination, no supervisor deadline and exit zero. `trial_accepted` is always false. A caller must independently require exact native counts/guards/cleanup, TLS completion, source identity, raw byte counts, strict padding and original integrity checks before accepting an extracted section. No firmware installation, UI, panel, reset, decrypt retry or acceptance of arbitrary inputs is present.

## Collection and cleanup

Raw helper stdout stays private and must be at most 1 MiB. Collection strips only lines beginning exactly `[GC_INFO]` using `index($0, "[GC_INFO]")`, writes private `stdout.safe.tmp`, verifies filtered output at most 4,096 bytes, then renames it atomically to `stdout.safe`. Non-prefix lookalikes remain visible. Native stderr is bounded at 4,096 bytes; supervisor stdout/stderr must be empty. Collection returns only the bounded filtered frame. It is a one-shot operation: an existing safe/temp file refuses automatic regeneration and preserves evidence for reconciliation.

Cleanup is explicit, after the caller has retained and validated relevant evidence. It requires the bound terminal receipt and no active bound child/supervisor. It validates a closed whitelist of regular single-link root-owned mode-0600 job files, refuses unknown/hidden/symlink/directory entries, removes only these fixed job files, and removes the empty job directory. Staged payloads and provisional plaintext remain entirely caller-owned; no recursive delete or broad kill is used. The caller separately removes exact pinned payloads and proves stage absence. A false refusal preserves artifacts.

## Host verification and remaining qualification

Run `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_job` and repeat with `python3 -O`. Sixteen tests pass in both modes. They exercise malformed specs/status/root replies, no replay on ambiguous launch, held-lock requirement, exact private intent accounting, actual CR launch size, real host proc parsing, absent-vs-unavailable proc behavior, exact GC filtering, and the receipt/exit race. Isolated local child sessions exercise successful completion and group deadline termination. Environmental preambles and the helper executable are replaced only for those explicitly local tests; production scripts are separately syntax checked unchanged. No actual target utility, handshake or live lifetime is qualified by these tests.

The parent controller owns actual target coordination. Its review must pin this module and all staged payloads, prove the native/channel deadlines in the source, verify target `setsid`/shell/group-kill behavior, keep the global lock through final artifact validation/cleanup, and preserve failed outcomes without replay. No additional user permission is introduced by this technical integration review.
