# Pure bounded SWU header authentication subset

`HeaderAuthentication.cs` is a net6.0 library with no file, console, network, TEE, root, target runner or native-platform calls. It accepts a caller-owned exact4032-byte aggregate, exact independently pinned public PEM bytes, and an explicit immutable public-key/wrapper-CRC anchor. It returns fixed status, representation and bounded counts. It exports no plaintext, signature, key material, descriptor body, guessed payload field or content-derived diagnostic text. All input-buffer snapshots are wiped on exit. The caller must wipe its own original private buffers and enforce the actual aggregate output count before constructing the4032-byte input; allocated capacity is not a count.

This library has not consumed actual decrypted plaintext. The parent's earlier BZ sequence success/count4032 is contextual evidence supplied by the parent, not an authentication result produced here. Actual selected public PEM bytes were parsed on the host only. No TV, TEE, target-library execution, root operation, acquisition, deployment or real plaintext export is implemented or performed in this directory.

## API for later independently reviewed integration

```
using SwuHeaderAuthentication;
ValidationResult result = Validator.Authenticate4032(raw4032, exactPublicPemBytes, PublicPemPin.Master);
```

`PublicPemPin.Master` pins the426-byte selected master public file SHA256 `ebf12ab9d4ef069e1a6030b8c3b117894746637715270f7e3d37d3cd737f71a3`, CRC32 `860be2ed`, RSA2048/signature256, and wrapper whole-plaintext CRC32 `cbcf1d91`. A public constructor permits independently pinned synthetic fixtures and other explicitly reviewed anchors; callers must never construct the anchor from decrypted fields. The PEM parser accepts one `RSA PUBLIC KEY` or `PUBLIC KEY` block, whitespace outside that block only, with exact pinned bytes/hash/CRC and key size. Private-key labels and concatenated PEM blocks are refused.

Result fields are `Accepted`, fixed enum `Reason`, enum `Representation` (`None`, `Raw4032`, `CanonicalPkcs7`), `SelectedBytes`, `PaddingBytes`, `RootCount`, `PresentRoots`, `CheckedLeaves`. `SignatureAuthenticityValidated` and `FramingSubsetChecked` are true only for accepted results. `FullSchemaValidated`, `MetadataPublished`, and `FirmwareApplicabilityValidated` are always false. Refusals expose no selected buffer/counts. No result carries a reference to input bytes. The library never retries a different representation after signature or framing failure.

A parent-owned consumer may later use accepted representation/counts while retaining its existing quarantine/wipe and cleanup guarantees. This task does not implement a plaintext file sink. An original4032-byte raw aggregate can include padding even when its selected authenticated stream is shorter; any later private output must preserve this distinction and must not claim all4032bytes are unpadded. A successful authentication subset does not by itself establish full schema, payload applicability or installation safety.

## Conservative representation policy

The supplied source trace distinguishes the4032-byte cipher/aggregate capacity from the unpadded stream consumed by the stock whole-plaintext CRC branch. The parent reports that actual BZ aggregate count is4032. Its raw-versus-already-unpadded form is not guessed.

The API computes CRC over the exact raw4032 bytes. Independently it checks whether the tail is canonical PKCS#7: last value1..16, that many identical trailing bytes, original block-aligned extent. Only then does it consider a second candidate with that exact tail removed. Exactly one candidate must match the independently pinned whole-stream CRC. Zero matching candidates refuse `RepresentationCrcMismatch`; two refuse `RepresentationAmbiguous`. A raw stream ending in a padding-looking pattern keeps every byte when only the full raw CRC matches. Invalid/zero padding is never an instruction to discard bytes; an independently CRC-matching authentic raw stream can remain raw. A later RSA/framing failure refuses rather than reinterpreting bytes or trimming another suffix. CRC alone provides no authenticity.

The stock decoder's permissive detectPadding zero-result fallback is deliberately not reproduced as an unconditional stripping rule. This two-candidate policy extends the previous padded-only host model to handle the parent's count4032 observation conservatively. It requires source-backed candidate forms plus independent CRC proof and then authentication. An authentic padded output with a different aggregate count remains outside this fixed API and is refused, rather than silently expanded or truncated.

## Checked authentication/framing subset

The library checks little-endian prefix key-file CRCu32 and declared signature lengthu16 against the independent key pin. Signature extent is the expected key size, never the untrusted declared size. It verifies SHA512 RSA PKCS#1 v1.5 over the exact selected remainder after the signature, using `RSA.VerifyData(..., HashAlgorithmName.SHA512, RSASignaturePadding.Pkcs1)`.

After verification it checks exact51-byte OUIT magic including NUL, bounded little-endian root count, canonical0/1 root presence, bounded descriptor-body lengths with minimum tagu32+mandatoryu8, canonical mandatory flags, and the21 source-mapped tags. Unknown tags are refused. Known tag18 CRC leaf must consume exactly9 body bytes; known tag16 RSA leaf must contain its established11-byte prefix and exactly its declared signature extent. Other recognized descriptor bodies remain opaque. Top-level roots must consume the entire selected signed remainder. This provides bounded root framing, not nested item/group interpretation, payload CRC/RSA scope validation, parsed names/keys or graph reconciliation.

The retained source mapping is `../swu-header-validation-20261027bx/validation-readiness.md` and `framing_model.py`, derived there from SWUCoreTV SHA256 `b8de9e31bf6e74cf9a1f3cfd2598658d978a4edd88b36d1c2f10129ccc8a2697`. Important anchors include plaintext CRC branch/prefix at0x1d660c..0x1d6802, signed-span drain0x1d569a, SHA512 selection0x327bbc/0x36c798/0x369926, PKCS1 numeric1 at0x327e56, verification0x3281d6, OUIT magic0x40b384, root reader0x2ac8c8, body length0x2a0d86 and exact consumption0x2a0e00. This implementation applies that retained bounded trace; it does not claim a new complete reverse engineering of unknown nested schema.

## Offline host verification

`HostTests.cs` is a separate executable; its file reads and fixture handling are not compiled into the library. `NuGet.Config` clears package sources. `Directory.Build.props` gives each project a separate intermediate path, avoiding shared project.assets/deps contamination between the library and test executable. The first same-directory build exposed that host packaging defect before a test could run; it was corrected before source freeze.

`generate-synthetic-fixtures.py` creates explicitly synthetic public test data and synthetic-only RSA private keys. Those private keys have no relation to the actual selected public key. OpenSSL signs the synthetic OUIT remainders, and Python zlib independently fixes each whole-plaintext CRC in `fixtures/manifest.json`; C# CRC values are never used to set these fixture anchors. No actual plaintext is used. The generator persists its synthetic keys so PKCS1 and zero-salt PSS fixture regeneration is deterministic. The tests pin every fixture/key asset by length/hash, then check expected CRC, representation, fixed refusal code and input immutability.

The53 signed/collision fixtures include16 valid canonical padding lengths,16 authentic raw streams with padding-looking tails, ordinary authentic raw data, known leaves, wrong signature/key/digest/PKCS1-vs-PSS, changed signed span and signed malformed framing. The deliberately CRC-ambiguous synthetic collision must fail before either interpretation is authenticated. Additional tests cover every noncanonical last-byte padding value, all16 mismatched canonical patterns, wrong whole-CRC scope, truncated/oversized counts, absent/malformed anchors, wrong public key, wrong declared signature size, private/doubled PEM, and independent CRC known answers. Actual selected PEM is checked only for fixed length/SHA/CRC and RSA2048/signature256 parsing; it is never used with actual plaintext here.

The host verification script builds/tests using the existing SDK with offline package sources, writes bounded build/test summaries under this directory, and verifies the library source has no prohibited I/O/platform references. It does not invoke any target runner. Portable IL build and host OpenSSL-backed RSA success do not yet qualify the target CLR's crypto-provider availability. Later integration and target result consumption require independent review while preserving the parent's bounded existing TEEC sequence and cleanup. No automatic operation or permission prompt is supplied by this library.
