# Fixed single-read stock TCON log probe

This is a host-built, **unexecuted on the TV** prototype for one read of `/sys/kernel/debug/tcon/tcon_micom_log`. It implements FD's bounded first-read candidate, rather than changing the controller event logger. FJ retained metadata confirms the debugfs node existed, debugfs was mounted, `sdp_tcon` was listed Live, and the on-disk module matched the audited source. That does not attest loaded instructions or connect this stock internal TCON/FRC buffer to the external RTP producer.

The executable accepts no path, count, timeout, driver setting or configuration argument. Default invocation is a zero-I/O dry report. `--self-test` and `--fixture` use fake operations and pinned host allocations only. `--execute` is the sole production entry point: it refuses outside little-endian ARM32 or root UID/EUID before opening the driver path. No target execution, root request, network connection, USB transaction, direct MMIO access, deployment or public publication was performed in this package.

## Fixed acquisition and receipt contract

Production first checks the fixed receipt stage `/tmp/tcon-log-single-read-20261028fk` using native `statx`, requiring a nonsymlink root-owned directory with mode0700 and explicit TYPE/MODE/UID/INO result masks. It creates exactly `read.receipt.json` with exclusive creation, nofollow and mode0600 **before** the debugfs open. The stage must already exist; this package has no root staging adapter. Fixed stage checks and file creation are separate syscalls, not an atomic path-ownership proof against another privileged process.

It then allocates a4096-byte array, initializes and touches every byte with0xa5, allocates the observation/bracket storage, and pins the buffer. One fresh native `open` uses read-only, CLOEXEC and the ARM O_NOFOLLOW value. One direct native `read` requests exactly4096 bytes into that pinned allocation; there is no managed buffering. Close is attempted exactly once in `finally` for an acquired descriptor, even when a read or timestamp fails. There is no open/read/close retry, including EINTR, and no seek, later read, mmap, ioctl, ACK, initializer, printer or driver write. Receipt output, hashing and base64 serialization occur after driver close.

The receipt contains:

- Each open/read/close attempt, return value and captured errno; errno is normalized to0 on successful libc returns.
- Six monotonic microsecond brackets, explicit failed-clock and exception masks, and acquisition acceptance. A read requires valid open-after and read-before timestamps. A failure while obtaining a close timestamp does not suppress the close attempt.
- The entire4096-byte allocation and its SHA256, plus the bounded returned-prefix length and SHA256. Retaining initialized bytes is intentional: the source ignores uncopied-byte results, so even a positive return can accompany unfilled bytes. The fill pattern is not an infallible detector of copied bytes.
- `completeLogProven=false`, `copyCompletionAttested=false`, `externalRtpProducerProven=false`, `loadedModuleBytesAttested=false`, `producerAtomicityProven=false` and `physicalPictureObserved=false`.

Acquisition acceptance requires a valid0..4096 read count, no reported errno on success, a successful single close, all brackets ordered, and no clock/operation exception. Zero and short returns are retained without retries. Acceptance establishes the bounded syscall lifecycle; it does not certify complete kernel-to-user copy, producer freshness, a complete log, absence of events, external RTP provenance or optical state. A close EINTR/error is refused and is not automatically retried because ownership may be ambiguous.

`read.receipt.json` is private and may contain proprietary or identifying log text. It must not be published raw. Native stdout is not the receipt channel; platform `[GC_INFO]` output cannot interleave into this exclusive file. The JSON encoder preserves the safe ASCII base64 alphabet without HTML `+` escaping; an explicit all-`+` base64 stress case prevents a sixfold size expansion. Binary data remains encoded; this private receipt is never an HTML fragment. A crash may leave an empty or partial receipt. File creation, close, output failure or process death has no automatic retry/reconciliation here. The file is not atomically renamed and has no replay-safe staging/cleanup wrapper yet.

There is no timer thread or forced signal. These synchronous syscalls can block, and `finally` runs only if control returns. A foreground timeout would not prove rollback or completed close. No kernel-operation duration or recovery guarantee is claimed.

## Why4096 is the required allocation and request

FD's source audit pins the226262-byte extracted `sdp_tcon.ko`, SHA256 `9b7c1cb8e2bb8d11e5465a41fa402e71bd8d15a5dabd6b3d76de98a7a42549ee`. The debugfs read callback is `.text+0x61b0`; the fops open is stock `simple_open`. At+0x61c8..0x61cc an unsigned16-bit header becomes32-bit `L=value+1`, range1..65536. The L<=4095 branch fails to clamp to the caller's count; small reads are unsafe. At fresh position0 with requested/allocated4096, both this branch and the large branch copy at most4096. The source starts at mapped buffer+4, so the maximum source endpoint is4100 within its128KiB mapping. Signed-INT_MAX/request and negative/wrapped-offset paths are excluded by the fixed first-read contract, not repaired by this program. No shared-buffer store/ACK was found in the bounded callback body; this does not establish every possible hardware side effect.

The fake arithmetic test exhausts all65536 header values for first position0. It is a source-bound model, not a measurement of live kernel behavior. A full4096 return can be a prefix; a short result has no atomic producer/header freshness proof. The inspected producer handoff in FF is an internal FRC shared-memory route; no source bridge to the external controller comparison is established.

## ABI and source lineage

`input-pins.json` retains only relative paths, sizes and SHA256 hashes for FD/FF source analysis, FJ runtime metadata, the extracted module, the retained ARM libc, and FG's existing native binding. No OEM bytes, runtime boot identifier or raw root response is copied into this package.

The retained `usr/lib/libc-2.30.so` is ELF32 little-endian ARM EABI5 soft-float. Its exported `open/read/close/getuid/geteuid` are GLIBC_2.4 and `statx` is GLIBC_2.28. The P/Invoke shapes follow the ARM32 libc ABI: fd/flags/return are32-bit `int`; `read` count/ssize_t/pointer use native-width UIntPtr/IntPtr; mode_t is unsigned32. Native `statx` uses a256-byte result with mode at28 and UID at20; TYPE/MODE/UID/INO masks are0x10b. The fixed ARM flags are O_CLOEXEC0x80000, O_NOFOLLOW0x8000, O_CREAT0x40 and O_EXCL0x80. Existing FG binding provides retained working usage of these symbols/statx layout. Symbol availability and source shape are source evidence, not a new live libc attestation. Native monotonic stamps use FG's existing Stopwatch conversion and remain in that process's clock domain.

## Host qualification and next integration boundary

Run `sh build-host.sh` from this directory. It uses the retained .NET6 SDK and an empty NuGet source list, with temporary build state under this directory's `host-environment`, not `/tmp`. Native fake tests check count/error paths, all six clock failures, single close after failures, positive-but-partial copy behavior, receipt bounds and the exhaustive first-read arithmetic. Python source/pin checks run normally and with `-O`, test default dry and unknown-argument refusal, and invoke `--execute` only on this x64 host where it refuses at the first ABI check before libc/driver operations. These are host checks, not target acceptance or injected kernel fault tests.

`host-build-checkpoint.json` pins the three deployable .NET files and test records; `source-inventory.json` pins authored files and outputs, excluding transient build files and independent reviews. The raw receipt cap is16384 bytes including the tested newline bound. No shell/root envelope is introduced, so no unverified command/response bound or cleanup claim is inherited from FG.

The final native fake suite passed **131289 checks across27 cases**, including65536 advertised-length values with two arithmetic checks each. The build passed with0 warnings and0 errors. Host qualification passed **106 checks normally and with `-O`**, with51 malformed receipt variants rejected and all11 retained input hashes verified. The synthetic full receipt is6477 bytes including newline; the fixed-field structural bound is6657 bytes, below the16384-byte inclusive cap. The target caps are one open, one read4096 and one close attempt, never a repeated read. Ordinary receipt/stat/identity operations are separate from those target-call caps.

`parse-receipt.py` is an offline strict verifier. It bounds input before parsing, rejects duplicate/non-JSON fields, verifies the entire4096-byte allocation and the declared returned-prefix hashes, enforces fixed count/path/limitations, and recomputes acceptance from typed lifecycle/error/clock fields. An unattempted read requires the untouched fill allocation. Valid open/read/close/clock refusals remain refused, and positive-but-partial data remains explicitly unattested. Its `fixture.json` contains synthetic host bytes only. It does not certify a target receipt's transport provenance.

Before any target use, a separate reviewed adapter must bind fresh runtime/module/path metadata and the exact payload pins, create the fixed private stage, perform one explicit invocation without retry, retrieve the fixed private receipt after terminal completion, independently parse/hash/count/bind it, and account for exact ordinary-file cleanup. It must retain ambiguous or missing receipts without repeating the special read. No live adapter or actual read is included in this host-only prototype.
