# Fixed SWU metadata adapter: implementation and readiness

2026-10-27 UTC. This work builds on the independently reviewed source prototype in `research-20261027-external/sources/minimal-swu-helper/`, which remains unchanged. All new writes are in this adapter directory. This worker made no TV connection, loaded no target library, invoked no real TEEC/TA function, deployed nothing and changed no firmware. The parent centrally owns any target operation. The helper is an acquisition/protocol milestone, not a blackout fix.

**The live adapter source is implemented and host-tested. Its output is diagnostic metadata only. Plaintext validity remains unverified, and all plaintext is currently wiped without being returned or saved.** A successful `quarantined` result means the fixed command sequence completed with bounded counts, not that a valid header was decoded or authenticated.

## Build and runtime route

The available qualified route is the existing .NET 6.0.428 SDK at `${S95F_EVIDENCE_ROOT}/live-cast/sdk/runtime/dotnet`, producing portable `net6.0` IL for the previously established TV ARM32 CLR 6.0.9. This is **not a native ARM cross-build**. No Linux ARM GCC/sysroot was located; the available Android NDK clang uses a different libc and was not used as a substitute.

The default entry point refuses all arguments and any process that is not little-endian ARM with four-byte pointers, before making platform/library/configuration calls. It then requires real/effective UID 0 and boot `00000000-0000-4000-8000-000000000000`. The existing managed TCON helper was read as runtime-route evidence and was not modified. The parent's eventual invocation must continue pinning `/usr/bin/dotnet`, the installed CLR and the exact deployed DLL/configuration artifacts using the already established runtime preflight.

`verify-host.py --deadline` rebuilds the portable IL, compiles an **x64 host-only dummy library**, runs the host tests, verifies default x64 refusal, and tests the native alarm deadline in an isolated host child. `host_mock.so` is a test fixture with seven versioned dummy exports; it contains no socket, device, file or TEE calls and must never be deployed to the TV.

## Host evidence

The final host suite covers three literal golden 60-byte frames; all eight failed TEEC stages; two successful output-size mutations; three excessive-count cases; twelve allocation-size/null-buffer/map/address faults; and three selector-drift stages. It verifies exact command budgets, ignored failed-call output, reverse cleanup and encrypted-input erasure. SHA-256 known-answer tests cover empty input and `abc`; retained-file checks independently verify all four ELF hashes and Build IDs, including vconf. File-guard tests use disposable public host fixtures for size/hash/identity rejection.

A separately compiled x64 dummy library exercises the actual fd loader, link-map and symbol-owner checks, all seven `TRUSTWARE3.0` resolutions and delegate signatures, and a native write at operation+56. These are host native calls into dummy functions, **not TV/TEE calls and not proof of ARM32 calling-convention acceptance**. The host-only test branch explicitly requires x64. The default x64 entry refuses with exit 64 before platform work.

`host-verification.json`, `host-test.log`, `host-guard.log`, `build.log` and `deadline-test.json` retain the results. The final deadline test must exit on signal 14 at approximately 25 seconds. `input-provenance.json` binds the supplied encrypted envelope back to retained prefix bytes `[234,4290)` and the original full-prefix hash. No payload bytes or plaintext are included in that input artifact.

## Remaining gates for one centrally controlled target test

1. Independently review the new adapter source and exact final IL artifact; the frozen C prototype review does not automatically cover this translation, native binding layer or file/deadline implementation. Host tests cannot establish target loader/CLR behavior.
2. Pin the exact deployed assembly, `.deps.json`, `.runtimeconfig.json` and `header-envelope.bin`, together with the established dotnet/CLR identity. Use the fixed deployment directory and restricted permissions, and exclude `host_mock.so`, host source and test artifacts. This worker created no deployment script and performed no target operation.
3. Use one finite parent-controlled invocation with an outer timeout longer than the internal 25-second deadline, exclusive/restricted diagnostic capture and no automatic retry. A timeout/termination is an indeterminate TA outcome, not a successful cleanup. Actual helper identity authorization, callback/transport behavior, hang behavior and TA persistent effects remain unobserved.
4. Treat a successful `quarantined` result as bounded command acceptance only. **No padding validation, OUIT parser, first-wrapper/plaintext CRC check or RSA/signature verification exists yet.** Plaintext is currently wiped and cannot be recovered from the diagnostic output. Implement and independently test those semantics offline before publishing any decoded metadata. No schema parser, automatic deployment, payload acquisition or firmware application is part of this work.

Full user authorization is already established; these are concrete implementation/evidence gates for the parent's coordination, not a request for repeated permission.
