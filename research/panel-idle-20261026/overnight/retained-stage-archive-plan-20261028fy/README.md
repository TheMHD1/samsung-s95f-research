# Fixed FW retained-stage archive plan

The existing FU sidecar fetch contract is sufficient for a narrowly derived **ordinary-file archive**, without invoking native code or touching USB. FU's accepted path itself cannot be resumed: FW was refused and its wrapper correctly made no follow-up requests. This plan separately reuses FU's source-pinned old `dir_guard`, `file_guard`, `exact_inventory`, SHA256 checks and exact `FN_SIDECAR` framing. Each proposed command strengthens the normal single-sidecar fetch by checking **all 11 expected stage files** before reading its one selected ring. There is no general path/size interface and no transport executor in this package.

The fixed stage and original source/receipt hashes are sealed in `archive-plan.json`. The known nine file entries reference existing host paths, lengths and hashes: three FN assembly payloads, three self-test receipt/diagnostic blobs and three native receipt/diagnostic blobs. They are not copied into this package or duplicated in a future archive. The other two expected files are baseline-ring.bin (15372 bytes, hash275e8bdbdeeb670429190cc7136d2715dcd2b25921ab7e6c2e8038f5a543b5f9) and post-ring.bin (zero bytes, SHA256 of empty). The original native receipt describes the baseline ring as complete but excludes its bytes; its post-ring is empty because no post-ring USB read was attempted. This archive must not reinterpret either state. The baseline filename does not prove a pre-fault snapshot: that ring read precedes the faulted pre-arm R read, but R may already have been faulted during the ring read. The logger was never armed. The zero-byte post ring is not a completed post-fault snapshot. Archiving cannot promote FW acceptance or satisfy FN's full two-ring observation binding.

The immutable independent phase proof has SHA25688c4dcbb4a3d8cd73741325cf0d8a04751e1d72cbc6171440036c6c0ae7c1542. It binds the original Ready/released/closed two-pair refusal, zero writes, no arm and no Left. The original enclosing root invocation completed and checked the expected private inventory, but the remote data have not yet been archived. Later USB65→66 re-enumeration is not a reason to invoke an old USB helper. Ordinary stage data are expected to survive a controller reinitialization within the same Linux boot; **fresh guards must establish their actual continued existence and identity**. No preservation is assumed across a Linux reboot.

The parent may prospectively submit `command-01.sh` and, only after its authenticated response has been retained and validated, `command-02.sh`, once each through the same pinned root adapter/serialization contract. Do not execute these files as target scripts; they contain the exact proposed inline ordinary command bodies, not deployment payloads. This package has not submitted them. Each body checks the exact Linux boot, UID/GID0, non-symlink root0:0:0700 stage, exact 11-name inventory including hidden-name enumeration, and each non-symlink regular root0:0:0600 file's exact size and SHA256. Then it prints the inherited frame and base64 for the fixed selected file. Each request repeats all guards. No mkdir/chmod/chown/write/delete/cleanup, dotnet/helper, USB/device operation, UI key, reset, instruction action, logger/threshold change or automatic retry is in either command. `umask` changes only the transient shell setting; ordinary reads can affect ordinary filesystem access metadata and are not claimed to be physically side-effect-free.

Every command must still meet the pinned root adapter's exact echo, authentication, root UID/EUID, remote zero exit, no timeout, no stderr and transport success checks. The request caps remain8192bytes, remote45/host75seconds, response65536bytes. Actual commands are6909bytes maximum. A representative full15372-byte ring reply placed into the retained root response shape is29550bytes, within65536; the hard adapter cap still applies to any real response. Frame parsing requires an exact prefix/suffix, canonical base64 (newlines permitted as in the original fetch), decoded exact length and native-receipt SHA256. The empty post ring is a valid empty payload between frame lines, not a failed capture and not a completed stock observation. A base64 transfer without matching length/hash is not an archive.

## Prospective private host commit procedure

The live parent should first rehash this sealed plan, commands, all pinned source/actual inputs and the nine referenced host originals. It must hold central target-operation serialization and confirm no known job is modifying this stage. Neither process inactivity nor stage coherence is magically attested by old snapshots. The original native terminal proof supports only that recorded invocation; the per-request file guards and content hashes supply current data checks, not an atomic whole-system snapshot.

Create a fresh absolute host archive directory with mode0700, refusing an existing directory/symlink and refusing duplicate invocation intent. Before a request, create a private intent/command record with mode0600. Submit each exact command at most once. Retain its complete root response/transport record privately with mode0600 and fsync; validate authenticated completion and strict framing before using bytes. Allocate at most65536bytes for a response and15372decoded ring bytes. Do not stream an unbounded result or use a read-until-EOF helper. For each output file use exclusive create and no-follow semantics (O_CREAT|O_EXCL|O_NOFOLLOW,0600), check exact write count, fsync the file and close. The parent already has a qualified root-call implementation; this plan supplies no new root client.

Write a private index that binds the current Linux boot, original phase-proof/receipt/root-ledger/manifest pins, the exact two commands and new root-response hashes, each archived ring length/hash, and references to the nine unchanged host source files. Include originalNativeAccepted=false/originalWrapperAccepted=false, no arm/no Left/zero writes, archive-only=true, remoteStageRetained=true, ringWrapExcluded=false and new USB work=false. Revalidate each host archive file's bytes/hash; fsync the index and directory before publishing a `complete` archive marker/index state. An optional atomic replace of an index within the private directory is a host bookkeeping action, not a target cleanup. It must not overwrite an unrelated existing archive. Until both files and the final index are durable, report the archive incomplete and retain any partial records.

Refuse missing/different boot, stage, file, ownership/mode, symlink, extra/missing inventory name, changed known-host byte/hash, source/phase pin, root or framing ambiguity, count/hash discrepancy, host write/fsync failure or duplicate output. Preserve whatever evidence was obtained, perform no remote deletion and no automatic retry. A first-request failure stops before the second request. The original FW refusal must remain untouched even when both files archive successfully. No new census, native launch, UI/reset, gate restore or cleanup is bundled with this operation. Do not use an old USB number or interpret file reads as a fresh USB phase proof.

## Host-only qualification

`build-plan.py` has fixed dry modes only: construct/verify or write plan and commands under this directory. It imports the frozen pure FU/old contract functions and strict FN parser, never a live root transport. Its input inventory pins the original receipt, root ledger, known nine host files, source parsers/guards and manifest. `parse_ring` is a pure parser; future callers must use the just-verified sealed plan, not a caller-provided substitute hash contract.

`verify.py` checks exact plan regeneration, both command hashes/sizes, `sh -n` syntax without execution, finite11/9/2 accounting, no target mutation/native/USB/key/delete command bodies, all-file guards and strict framing. It tests a full15372-byte **synthetic** ring using a correspondingly synthetic expected hash, actual empty-post acceptance, 17 malformed/type/name/size/hash/framing refusals, and representative response framing. It never reads actual baseline ring bytes from the target. Normal and optimized outputs are identical:52checks,2shell-syntax checks,max6909command bytes. This is a prospective design with a bounded builder/parser, **not an executed archive**, deployment, accepted observation, source-event completeness proof or cleanup record.
