# Evidence graph contract and provenance

`graph.json` uses `s95f-evidence-graph-v1`. It is data only. Neither the builder nor validator imports vendor code, deployment tools, or executable attributes from graph records. The builder reads bounded authored reports and two frozen contribution JSON files. A graph traversal does not execute a command or establish that adjacent facts occurred together.

Nodes have a unique `id`, a normalized `kind`, `label`, `source_refs`, and explicit `limitations`. Kinds are asset, function, interface, state, observation, hypothesis, action, gap, case, configuration, evidence or report. Address-bearing nodes identify `address_domain`; image VA, file offset, CPU SRAM, remote controller alias, Linux ELF link VA and live process address must not be silently substituted.

Edges have unique `id`, existing `from`/`to`, a concrete `relation`, `evidence_type`, `evidence_refs` with a locator, and limitations. `observed` means a retained observation within its stated scope; `static` means source/disassembly dataflow; `inferred` means an interpretation requiring assumptions; `unknown` marks a missing bridge. An observed edge also has `observation_class`: native_capture, owner_report, cached_ui or host_validation. The classes are provenance categories, not numeric probabilities. No percentage confidence is assigned.

Source references use retained-root-relative authored evidence paths with SHA256 of their original retained bytes. The original research root can verify them with `--retained-root`; a redacted public snapshot may intentionally have different report bytes and can validate structure without that flag. Export source/public manifests provide the separate transformation provenance. SHA equality is an identity check, not semantic truth or an OEM trust-chain claim.

The graph pins the complete initial DE and DF contribution JSON files before normalization. Original node and edge indexes are preserved as JSON-pointer locators. Kind names are normalized; DE categorical confidence labels are removed because `evidence_type` already states the category. OEM/private input references become pointers to the authored contribution and findings. Public asset SHA/address/file-offset metadata remains in `asset_anchors`, with explicit asset-only identity scope. No private prototype path or input inventory is copied into the normalized graph. An extra asset node links each DE object to its exact static anchors. This does not promote packaged identity to running-image identity.

DF's initial host-only prototype, later deployable eight-window capture, and later cross-core SLG addendum are separate evidence snapshots. The graph connects them without silently changing the first contribution. The SLG context bridge is source-backed. The Linux FRC-to-AP_EXCO field bridge, whole executing image identity, physical aperture producer and electrical/optical effect remain explicit unknowns.

Validator limits: at most10,000 nodes and50,000 edges; bounded identifiers/labels/relations/references; unique identifiers; non-dangling endpoints; permitted provenance categories; authored relative paths without private components; SHA syntax; explicit address domains; original source containment, maximum8MB and hash checks when a retained root is supplied. It rejects duplicate/dangling records, unsupported observation classes, missing address domains, private/traversal paths, hash drift, secret-byte field names and invented confidence fields. Successful validation proves graph consistency under these checks, never truth or running-image qualification.

Tests include independent minimal graphs, changed source bytes, malformed IDs/endpoints/categories, path/digest/domain refusals, private/secret field refusals, frozen contribution drift, private-reference removal, and preservation of the static versus unknown cross-core edges. All tests run without target libraries or a device.
