# BH owner-paired recovery and recurrence

Two facts are now physically observed: the picture returned after a stock controller restart, and pressing Home subsequently exposed For You for about one second before persistent black returned. This is a tested recovery with recurrence, not prevention or a permanent repair.

The owner initially reported persistent black. The unchanged X observer independently returned stop1/fault0x1001/gate0. A separately guarded, one-shot stock MODE2 controller off/on was then dispatched; Linux did not reboot. The owner reported a visible screensaver twice and explicitly had not pressed a button. Fresh USB metadata identified the next controller instance48 on the same Linux boot. After independent narrow lifecycle/cleanup review, a delayed unchanged X run reported80clean cycles over20s with retained RT0/0/1. The owner confirmed the screensaver was still visible. This establishes physical recovery and a paired later clean sampled state. It does not time the exact clearing or prove MODE2's exclusive causality.

A second20s unchanged observer was intended for one Home transition, but ended clean. The owner's actual keypress time was not established inside that interval. The owner then reported Home -> For You visible about1s -> persistent black. One later unchanged X returned AlreadyFaulted with RT1/0x1001/0. No onset was caught; that timing failure is preserved. See [four-observation audit](x-review.md) and owner observation JSON records.
