# Dense reference-refresh onset trial

The intended diagnostic is one normal Left from a prepared Apps header, with the unchanged original alternate threshold 40. EM must first be built and independently source-reviewed. No executable controller hook, protection change, boot/flash change, arbitrary register access, or permanent logger is part of this trial.

Sequence: start the existing private DH static kernel trace; use the existing bounded normal UI helper to wake and prepare Apps/header; take a fresh accepted EB baseline; if clean at40, run one EM capture and reconcile its exact parser/receipt; then take one separately qualified EB postcapture. All root/USB operations remain serialized. The private trace is stopped and collected even on a known-phase refusal where doing so requires no vendor command. Its90-second watchdog bounds trace enablement if coordination fails.

A faulted baseline does not authorize a key attempt. A classified accepted EB fault may admit the already reviewed one-stock-MODE2 recovery, with new USB identity and a separate clean readback; that recovery ends this trial rather than retrying the onset automatically. A missing/short/unknown vendor phase stops new headers, retains original evidence and precludes blind reset.

Readiness binds the latest accepted complete-pair state and fresh cached identity/no-holder checks. A phase note is a closed-world coordinator premise, not physical endpoint queue proof. A successful normal key command is not proof that UI consumed it. A cached destination change is UI evidence but no measurement of panel light.

The native reader and kernel trace have separate clock provenance. Do not subtract their timestamps without a qualified common-clock mapping. Use the outer sequence as an envelope and each stream's own event ordering. Report trace overrun/missingevents/watchdog effects. A 25 ms requested schedule cannot establish a25ms actual period or complete function-call coverage.

All outcomes, including no transition or an already-latched fault, remain separate cases. Preserve original40 throughout. If the software state faults, do not claim a physical blackout or light recovery without an independent observation.
