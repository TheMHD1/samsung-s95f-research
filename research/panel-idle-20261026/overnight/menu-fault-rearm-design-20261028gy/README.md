# Menu fault rearm: source control path and emergency-state boundary

**The next useful step is a fixed read-only image0 emergency-state witness, followed by the stock reset-domain closure being pursued in GZ. A three-halfword root rewrite is not a qualified physical recovery.** A two-halfword scanner-rearm hypothesis is precisely specified below, but is not implemented or admitted for execution here. GU HDMI selector work was stopped and retained as a disabled, partial checkpoint; this work returns to the main ForYou/Apps problem.

This host-only design reads selected source bytes and retained data, performs instruction checks and pure integer/state tests, and sends no requests. It creates no writer, runtime helper, root command, executable patch, MMIO operation or deployment. Original/frozen sources are unchanged. No firmware execution is used in the audit.

Fixed getters establish image0 AP `0x2000f0e0`, AP_EXCO data `0x2000ff14`, AP_EXCO context `0x200158a8`. DW's tag0 mapper translates source SRAM pointers by adding `0x25000000`; the matching complete proposed intervals are:

This is36bytes/3read pairs, no MMIO. All intervals are within the mapper's image0 SRAM domain. Existing EB M/C/D and N are image1/local or distinct descriptor windows and do not sample these fields. The exact36byte USB/DMA intervals are **source-qualified proposals, not previously live-qualified USB reads**. Source alias qualification is stronger than guessing a high bank, but does not prove endpoint accessibility. A new fixed allowlist/helper must be reviewed before any parent invocation; no alternate bank/fallback/retry is included. The audit emits only proposed headers and hashes, not OEM payloads.

This witness can test whether the reason and guard words currently match the static path. It cannot identify the controller PC or prove a particular reset branch executed. Prefer closing GZ's stock receiver/emergency-loop service path before a control-only intervention, because it may provide the legitimate reversal for the hardware and handshake state above.

## Precisely bounded scalar alternative, not an admitted fix

The smallest local scanner-permission change is **two** halfwords, retaining the historical fault code:

`(stop,fault,ordinary) = (1,4097,0) → (0,4097,0) → (0,4097,1)`.

Keep ordinary0 while changing stop to0; enable ordinary1 last. The first stage remains scan-disabled. The second requests local scan permission, while the independently checked fault lowbit remains active. It must be labelled **scanner rearm with retained fault**, never Clean0/0/1 or physical reset. It may be promptly turned off by the image0 consumer, and may enable image1 work while image0 remains in emergency service. Retained H/history/references may immediately retrigger the same setter. That outcome is informative but not a working fix.

A third halfword fault240a→0 would produce the familiar Clean tuple synthetically, but no qualified runtime fault-clear semantics or reverse-hardware sequence supports it. It would also erase the lowbit witness. **Do not include this third write in a first implementation on the evidence here.** Restoring startup47bc bytes, clearing N/history/arrays, changing2408, threshold, lane tables, GPIO, power, persistent parameters or executable code would expand the experiment and is outside this design.

The two exact design packets are command0x102/address`0x47012400`/length2/payload`0000`, then command0x102/address`0x4701240e`/length2/payload`0100`; little-endian headers are emitted by the pure audit. Neither packet is sent or packaged as an executable writer. The new addresses/semantics need a separate fixed contract despite FA/FM's positive prior two-byte transport evidence.

Any future implementation needs all of the following concrete boundaries:

- Fresh same-boot/device/descriptors/FD ownership, accepted closed-world first-header premise, no holders, original complete knownReady/released/closed receipt, exact staged source/manifest, bounded exclusive receipt and a central ownership ledger. Current GP metadata is a historical admission input, not a future readiness decision.
- Full baseline R/M/C plus required callback identity; explicitly admit source-qualified **fault/AA0/AC3** only if still present, with root/geometry/global selector/threshold40/logger0/finite source controls exact. Do not transplant FA's Clean/AA0AC2 guard or its thermal policy as a substitute. Freeze a transaction-local context tuple and retain baseline/fresh/readback bytes. Any legitimate publisher/context drift may conservatively refuse; no unbounded wildcard profile.
- Fresh M/C and R immediately before the first change. After each complete two-byte write, full R readback must show the intended exact halfword and unchanged fault code/logger/threshold. Whitelist only the intended scalar; all other changes require explicit source-qualified handling before implementation. No claim of atomicity, continuous quiescence or cross-core exclusion.
- Fixed single-owner full-header/pending-payload obligations identical in principle to FA: after a fully accepted header, complete its promised payload even if a clock check failed; then stop. Short/exception ambiguity sets Unknown and forbids another header, retry, rollback, reset or alternate operation. No exception may claim a scalar stayed unchanged after an ambiguous write.
- A distinct observational parser must preserve `(0,4097,1)` rather than project it into Clean for ER/FN admission. The existing readers' accepted state schemas do not qualify this new observation. No UI transition or further experiment should be hidden inside the writer.

If a knownReady interruption occurs after stop0 but before gate1, ordinary remains disabled; record exact partial ownership and reconcile separately. If gate1 was read back and a bounded diagnostic terminates with known phase, a separately reviewed rollback would first request ordinary0 and verify it, then stop1 and verify it, preserving fault4097 and all other bytes. This restores the **original two scalar values only**, not emergency/hardware/history state. If the source has already changed either owned scalar or context, do not overwrite it as a blind restore. Unknown phase prohibits even this rollback. No automatic stock reset is a replacement for restoring an owned scalar.

## Reproduce and interpretation

Run `PYTHONDONTWRITEBYTECODE=1 python3 audit.py` and the same command with `-O`; compare their JSON byte-for-byte. The script imports the already retained Capstone decoder under `/tmp/tcon-capstone`, reads source in place, and creates no native bindings or target adapter. Meaningful tests cover all local stop/gate domain combinations, fault lowbit values, malformed state types/tuples, forbidden addresses and exact packet integer layouts. Every retained input and14 bounded source spans are pinned.

The positive result is a concrete external-RTP fault-to-emergency-reason source chain and a small next RAM witness, not a root cause or permanent fix. Any proposed recovery must account for both root-latch state and the independent emergency effects. There is no optical proof, live PC proof, full writer census, electrical safety inference from memory values, kernel-status identity claim, or assumption that clearing a software tuple restores the damaged panel.
