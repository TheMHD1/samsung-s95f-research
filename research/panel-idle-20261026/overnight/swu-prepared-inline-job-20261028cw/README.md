The parent recorded that actual CV02 refused before executing the supervisor: retrieved private child/worker files were respectively one and two bytes longer than generated originals, solely because backslashes in their printf newline formats were doubled. The exact script SHA gates correctly prevented launch. No supervisor/child/native output markers or TCP connection were present. This failed outcome and the earlier CM01 UEP refusal remain preserved; CW does not reinterpret them as success.

The retained root agent explains the transport behavior: `root-access/source/payloads/common/SamsungTvRootAgent.cs` SHA-256 `3b53e8c9de66331ca5336f57bc8eba33adf66ca2860a29daedbbeb3a98ea8405`, lines 343 and 601–603. `ProcessStartInfo.Arguments` receives `QuoteArgument(command)`, and that function doubles every backslash before escaping double quotes. Root command text containing a single-quoted script literal therefore does not have a byte-preserving path for its backslashes in the observed target runtime. CW changes neither this root agent nor its authentication/serialization protocol.

CW adds `preparation_commands(spec)`, returning four fixed ordered commands: exclusive private job directory creation after exact payload guards, then base64 preparation of plan, child script and worker script. Each write has a nonexistent/non-symlink destination check, private permissions and exact size/hash readback. The base64 literals have a safe alphabet and carry no literal script backslashes through root command quoting. Every preparation command is bounded below 8,192 bytes. For the frozen five-file CR-shaped spec their sizes are 2,425 / 906 / 2,721 / 4,863 bytes. The actual script text is recovered byte-for-byte before any launch is attempted.

`launch_command(spec)` is now a separate 3,768-byte guarded operation: exact payloads, private job/plan/script metadata and hashes, exclusive `launch-once` marker, and the same hash-bound inline `setsid /bin/sh -c "$(cat fixed-script)"` launch. The supervisor independently checks the child hash before inline execution. It retains all CV process identity, go-marker, native/supervisor/host lifetime, status, GC filtering and cleanup semantics. The cleanup whitelist includes only the fixed new launch marker alongside the prior known files.

`run` performs the four preparation commands once each and records preparation as a distinct non-native phase. It creates no launch intent until all preparation succeeds. Every ambiguous preparation is retained with launch_attempts=0 and no retry. The job's host deadline begins immediately before launch; preparation itself has a finite four-short-request budget (at most four nominal 25-second request attempts). `Access.last_response` is assigned before validating a returned root frame so the parent can privately retain a rejection's exact exit/stderr metadata; it is cleared before each new submission and is not printed by this library.

# Fixed SWU background job lifetime contract (CW)

This is a host-only lifetime library for one fixed, separately reviewed .NET section helper. It has no execute CLI, no staging, no TLS implementation and no target action on import. Tests do not contact a TV or root controller. The implementation does not modify the existing access client, persistent daemon, target root agent, TEEC frames or streaming engine.

## Why a background job

The existing access CLI and persistent daemon each reject foreground execution above 120 seconds. Increasing a host timeout alone cannot bypass that limit. A 1.455 GB section can require a longer lifetime. CW submits one short launch command, detaches a fixed helper with all inherited standard handles redirected, and observes it through short authenticated persistent-root requests. Bulk plaintext continues through the separately reviewed private TLS channel, never the root response frame.

## Public API and composition

`Payload(name,size,sha256)` and immutable `JobSpec(stage,dll,boot,dotnet_sha256,payloads,native_seconds,supervisor_seconds,host_seconds,io_seconds)` describe exact inputs. Stage names follow `/tmp/swu-stream-20261028xx`; the entry point is always `SwuStreamTarget.dll` without arguments. There is no shell command or executable field. The caller supplies the frozen full deployment payload pins and verifies all declared timeouts against the target source/configuration. CW does not infer native alarm configuration from a DLL.

`guarded_access(pinned_access_path)` is an explicit live context manager, to be used only by a centrally coordinated adapter. It hashes the exact existing access source before loading those same bytes, holds its existing global flock for the entire context, checks the original firewall, route, public model/developer host, ready persistent channel, root identity and build, and yields `Access`. Every `Access.exec(fixed_command)` uses the imported `persistent_request` once with a ten-second remote timeout and a 25-second socket timeout. It rejects non-root, timeout, nonzero-exit, stderr, malformed and oversized responses. No bootstrap/acquisition or alternate root path is supplied. Direct same-UID daemon clients remain subject to central coordination.

Within that same context, a controller may pin/recheck staged payloads and start its TLS listener, call `run(access,spec,private_empty_evidence_dir)`, collect native status, validate the separate TLS artifact, and only then clean up. `run` requires the held-lock capability. It records a preparation plan and exclusive intent/result for each of four preparation commands, dispatching each once. A preparation failure records zero launch attempts and produces no launch intent. After all four pass, it persists a private exclusive launch intent before one dispatch; no ambiguous preparation or launch is replayed. The evidence directory must be empty, owned by the current user, non-symlink and mode 0700. Intent/terminal/reconciliation records use exclusive no-follow mode-0600 creation and fsync.

Builders `launch_command`, `status_command`, `stop_command`, `collect_command` and `cleanup_command` are exposed for review and composition. They accept only the validated immutable spec. For the frozen five-file CR deployment the launch is 3,768 bytes, below the existing 8,192-byte command limit. Syntax checks use the actual generated scripts. The `run` method records only bounded status metadata; callers should log each fixed root request/response privately through a wrapper if full authenticated transport provenance is required.

## Target supervisor and exact ownership

Preparation and launch verify stage root ownership/mode 0700, exact payload files (regular, non-symlink, single link, mode 0600, exact size/hash), boot and `/usr/bin/dotnet` hash. Preparation exclusively creates `cm-job`, then writes the plan and fixed child/worker scripts separately through safe-alphabet base64 with exact size/hash readback. Launch requires the exact private prepared files and atomically creates the `launch-once` marker with POSIX noclobber before dispatch. A duplicate launch refuses even if no identity marker became visible. `setsid` availability is checked before dispatch. The root shell redirects stdin/stdout/stderr before launching the detached supervisor, allowing the root request to finish without a descendant retaining its capture pipes.

The supervisor and fixed child each acquire their own session/process group. Each reads its own kernel start time and requires PID=PGID=SID. The child publishes its identity, then waits for a bounded go marker before executing dotnet. The supervisor verifies that published PID is its exact child and that boot/start/group/session still match before allowing execution. It polls that same identity using kernel uptime. A deadline kill targets only that verified child group. A PID mismatch, unreadable live proc record, malformed identity or unexpected group never authorizes a kill.

`proc_identity` suppresses the expected cat diagnostic from a disappearing proc stat file. It classifies absence only when the process directory is absent and `/proc/self/stat` remains readable. Other read/parse errors abort. This is an operational classification under a healthy mounted root procfs, not universal proof that an arbitrary process or descendant has terminated. Ordinary exit polling distinguishes this absence from unavailable evidence. The status reader also rechecks the atomically committed exit receipt if the initial receipt test preceded supervisor disappearance; it does not turn a normal exit race into a failed root response.

The supervisor commits a private atomic exit receipt with the immutable job digest, native exit code, deadline flag and direct-child termination classification. The child has no subprocess API in the reviewed helper. A future helper that can spawn descendants requires its own descendant-quiescence review; CW does not infer that all descendants have died merely because a group leader disappears.

## Bounds and failure behavior

Native alarm must be enabled before native/I/O work and be at most 1,700 seconds; the separate channel must have its own total and per-I/O limits (per-I/O at most ten seconds). Supervisor lifetime is at most 1,750 seconds, with at least ten seconds beyond the declared native alarm. Host policy is at most 1,800 seconds and reserves 50 seconds beyond the supervisor for one final bounded status request and one conditional stop. These are bounded process-level attempts. Kernel uninterruptible I/O or a broken lower transport is not made interruptible by this library.

If the supervisor deadline expires, it sends SIGKILL to the bound child group, waits a bounded observation interval and avoids an unbounded `wait` on a still-live task. Unconfirmed termination is explicit and never accepted. Host deadline sends one conditional stop request; this is not a native retry. Missing replies, unexpected frames and interruption produce a reconciliation-required record and retain the job. No new run is attempted. If the host disappears, the remote supervisor and native alarm remain responsible for bounded termination attempts. Releasing a host lock after failure is not permission for concurrent vendor work: the central controller must first reconcile retained state.

`transport_completed` requires confirmed child termination, no supervisor deadline and exit zero. `trial_accepted` is always false. A caller must independently require exact native counts/guards/cleanup, TLS completion, source identity, raw byte counts, strict padding and original integrity checks before accepting an extracted section. No firmware installation, UI, panel, reset, decrypt retry or acceptance of arbitrary inputs is present.

## Collection and cleanup

Raw helper stdout stays private and must be at most 1 MiB. Collection strips only lines beginning exactly `[GC_INFO]` using `index($0, "[GC_INFO]")`, writes private `stdout.safe.tmp`, verifies filtered output at most 4,096 bytes, then renames it atomically to `stdout.safe`. Non-prefix lookalikes remain visible. Native stderr is bounded at 4,096 bytes; supervisor stdout/stderr must be empty. Collection returns only the bounded filtered frame. It is a one-shot operation: an existing safe/temp file refuses automatic regeneration and preserves evidence for reconciliation.

Cleanup is explicit, after the caller has retained and validated relevant evidence. It requires the bound terminal receipt and no active bound child/supervisor. It validates a closed whitelist of regular single-link root-owned mode-0600 job files, refuses unknown/hidden/symlink/directory entries, removes only these fixed job files, and removes the empty job directory. Staged payloads and provisional plaintext remain entirely caller-owned; no recursive delete or broad kill is used. The caller separately removes exact pinned payloads and proves stage absence. A false refusal preserves artifacts.

## Host verification and remaining qualification

Run `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_job` and repeat with `python3 -O`. Nineteen tests pass in both modes. They exercise malformed specs/status/root replies, no replay on ambiguous launch, held-lock requirement, exact private intent accounting, actual CR launch size, real host proc parsing, absent-vs-unavailable proc behavior, exact GC filtering, and the receipt/exit race. Isolated local child sessions exercise successful completion and group deadline termination. Environmental preambles and the helper executable are replaced only for those explicitly local tests; production scripts are separately syntax checked unchanged. No actual target utility, handshake or live lifetime is qualified by these tests.

The parent controller owns actual target coordination. Its review must pin this module and all staged payloads, prove the native/channel deadlines in the source, verify target `setsid`/shell/group-kill behavior, keep the global lock through final artifact validation/cleanup, and preserve failed outcomes without replay. No additional user permission is introduced by this technical integration review.
