# DT fixed-reference candidate reader

Host-built additive derivative of frozen DM, source-qualified by frozen DR. This checkpoint has not run on the TV. Parent alone coordinates any target request after independent review. No UI, MODE2, key, controller write, reset, automatic recovery, background loop, or retry is implemented.

The native program retains all12 DM reads and inserts `fixed-top-candidate` bus0x47015354/104 and `fixed-bottom-candidate` bus0x47016264/104 after Diff and before end-N/end-R. Full success is14 headers and28 bulk calls; all headers are target0x101. These fixed SRAM payloads are packed12, not u16 and have no embedded header/channel/epoch tag. Pure host decoders select x570/571/622/623/624/625/632/633 using the first102 bytes and ignore two tail bytes. The new fields are named candidates; neither transport acceptance nor matching values establishes the historical A branch.

Before either new header, completed M/C must show root0x20010000, packed span2880, lanes1920, xBase0 and context geometry2160/1920/2880. Drift refuses at ReadyForHeader with no candidate-window header. Original DM controller transfer/phase logic and DQ-derived native binding are preserved byte-for-byte: preflight, FD identity, preclaim absence, claim, postclaim native GETDRIVER/canonical inode qualification, matching IN obligation, original40s lifetime and4s remaining-pair budget, release/close finally. The same kernel cached GETDRIVER ioctl is used; no USB control-transfer path is added.

The reader permits postfault R state. Root/packing qualification is stronger than DM's interpretation-only context report; recovered changing profile values such as R+0x20/R+0xbc/R+0x98/R+0xac are retained without inventing new invariants. Existing source asset/runtime lineage is not whole running-image or callback attestation. No dynamic ring address or aperture alias is introduced.

`run-once.py` is dry by default. Its reviewed manifest and exact local readiness file+SHA are required before root transport import. The readiness schema is `dt-rtp-fixed-reference-readiness-decision-v1`; the exact boot, current device number, metadata, no-holder census and closed-world ReadyForHeader lineage must be supplied by the coordinator. The wrapper imports the same pinned frozen passive-wrapper utilities/root adapter as DM, creates one private `/tmp/researcher-dt-<32hex>` stage, pins three payload files, runs exclusive-file fake selftests, rechecks metadata, invokes once, parses only the exclusive structured receipt, saves raw files, checks final metadata/inventory/hash, and removes exactly the known stage contents after accepted completion. Ambiguous dispatch/failure leaves evidence/stage and does not retry or infer cleanup. stdout is diagnostic, not semantic receipt.

Native receipt names remain fixed exclusive0600 files inside a0700 owner-checked stage. The bound remains24576 bytes. Native selftests exercise adversarial plus-heavy Base64, long timestamps and a late escaped error with the actual serializer. Host wrapper tests cover parser mutations, semantic packing drift, declared frame/count errors, shell syntax/8192-byte command bounds, native exclusive-file receipts and failed-stage policy. Host test temporary directories use caller TMPDIR; no TV/root calls occur in those tests.

Build: task-owned HOME TMPDIR plus the retained .NET6 SDK; `dotnet build -c Release --nologo`. Verification: `dotnet bin/Release/net6.0/RecordCapture.dll --self-test`, `python3 verify_source.py`, `python3 test-runner.py` and optimized Python repeat. Default invocation of both native DLL and wrapper is dry. `deployment-manifest.json`, `source-inventory.json` and `host-validation.json` pin the final checkpoint. Build/test status is host-only, not target qualification.
