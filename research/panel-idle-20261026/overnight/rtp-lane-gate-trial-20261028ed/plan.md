# First lane-gate data capture: coordinator plan

The parent remains the sole target coordinator. EB is an offline-built,
read-only extension of DT: its16 fixed read pairs retain all prior reference
and record windows and add136 primary-table bytes plus68 secondary-table
bytes for lanes568..635. No address arguments, code write, bit change, UI key,
reset, fallback, retry or background task are proposed.

Freeze and independently review EB before target use. Its concrete context
guards must bind root0x20010000, xBase0, packed geometry1920/2880 with the
matching C geometry, and the ordinary operating-mode condition. A locally
admitted lane is not proof that execution visited it; an earlier comparator
can exit the loop. Tables, context and records are sequential samples.

The current vendor-OUT predecessor is DY/code-read-01: four complete read
pairs, ReadyForHeader, released/closed and STAGE_ABSENT. No target operation
has run since it. This preserved predecessor and fresh cached identity/holder
metadata supply explicit coordinator premises, without endpoint-queue or
continuous-absence proof. A boot, instance, binding or holder discrepancy
refuses before the first production header.

Any accepted header obligates its matching transfer. A short/failed/ambiguous
bulk stops all later headers; a guard refusal retains the actual completed
pair count. Preserve every refusal. Cleanup follows reviewed acceptance and
exact stage-identity rules. Do not automatically reset, retry or modify an
observed eligibility flag.

The observation will measure actual table bytes for the first time in this
work block. It will not establish historical mask values, gate-body execution,
table writer completeness, physical pixel mapping, a safe modification or a
blackout fix. Proposed instruction hooks remain uninstalled.
