# Live+saver stock MODE2 prerequisite: source-backed design

A narrowly qualified **Live+saver stock reinitialization experiment** is implementable without changing the native MODE2 helper, ioctl, three payloads or deadline. No intrinsic Apps/current-tab requirement was identified in the inspected EI/BV/DH source path or fixed native ABI. Apps is nevertheless a meaningful **empirically qualified recovery policy**, not meaningless padding: BV documents the owner-observed populated-Apps sequence, and current EI admission implements that sequence above the helper. The candidate below needs a new host family, manifest and independent review; it is not a relaxation of the frozen Apps recovery helper and has not been executed here.

The purpose is to establish a fresh clean controller baseline **while the normal UI remains cached Live+saver**, so a later unchanged one-Left recorder can arm before an intended wake. It does not promise that MODE2 will leave the UI context intact, produce clean R, clear all domains, reload instructions, or restore emitted light. It must report an unavailable baseline if the required state does not result. No ScreenSaver launcher, wake, navigation, flash/debug instruction or threshold/mask operation is proposed.

## Source findings and latest retained baseline

* EI `recover-eb-fault.py` first requires the exact accepted EB result/manifest, complete16raw inventory and stable full start/end R fault tuple1/4097/0/40. Then it may send Right, calls BV `apps_gate`, keeps BV `public_gate`, calls DH fixed deadline helper, and accepts a final cached Apps result. The navigation and Apps acceptance are host-level gates.
* BV `apps_gate` calls calibrated NAV with actionApps and demands a successful Apps result. BV README explicitly ties its procedure to owner-observed recovery after reaching the populated Apps page. This is positive operational lineage, not a claim about every UI context.
* BV `public_gate` checks software-upgrade working status0, display powerlcdon, screenstate1 and public burn-in-progress0. They are reject signals, not a global idle, panel-light or saver-internal-state proof. Preserve all four, the exact command bodies, source pins and bounded DBus reply timeouts.
* DH `run-deadline-mode2.py` pins operation41/mode2/deadline12seconds, original stock source/CLR/module checks and three immutable payloads. Its native Program has no tab/window getter or input-key API. It validates ARM32/root/16-byte request offsets, uses fixed `/dev/tztv_tcon` request0xc010749f with41/2/0/0, oneopen/oneioctl/finallyclose, arms SIGALRM12seconds before deviceopen, and produces an exclusive receipt separate from runtime stdout. The native result is kernel_return_zero_only, with recovery/physical/power-action inferencefalse. No lower hardware equivalence across UI states follows merely from this absence of a tab check.
* The audited stock lifecycle reaches GPIO/reset callbacks, host USB disconnect/new enumeration and I2C setting replay. This is source/runtime support for a reinitialization experiment, not cold-boot, all-RAM clearing, code reload or electrical proof.

The newest frozen FW validation EB is accepted16headers/32bulks onUSB66, same Linux boot and descriptors after the separate Apps MODE2. Full start/end R are equal Clean0/0/1, c440/logger0; N windows are zero. The final cached UI is Apps+saver/CSFS. These observations do **not** satisfy a Live+saver candidate and do not justify automatically navigating into Live under this procedure. The original FW early fault/refusal, later accepted fault EB, recovery and archive remain distinct immutable records. GB's checker strictly parses the latest EB and verifies its16retained raw files; it does not rerun the older complete workflow.

## Smallest implementable source derivative

Prefer two small new host files, with no C# rebuild:

1. An EI-derived coordinator replaces **all** navigation/`apps_gate` calls and finalApps acceptance with the new read-only Live+saver context policy below. Keep exact EB fault/result/raw/source admission and public rejects. The coordinator never imports a top-level live executor as a library and is dry by default.
2. A narrow DH Python wrapper derivative retains its payload contract, staging commands, exact native invocation command, strict framed receipt parsing and exact cleanup body. Insert a fixed public-gate call and strict cached Live+saver snapshot **after staging, immediately before the native invocation**. This must be an explicit source delta in the wrapper; do not intercept arbitrary root commands with substring matching or add caller-provided callbacks/paths/actions. Both files receive new schemas/manifests, with original DH source and all three unchanged payload hashes recorded. The payloads may be referenced in place with their hashes rechecked.

Checking Live+saver only before `helper.execute` is insufficient for the chosen freshness contract: payload staging occurs inside that function before its native request. Refactoring the reviewed execute flow at this explicit boundary is the only necessary native-submission change. No instruction or executable patch is involved; changing the Python orchestration does not modify the fixed target assembly. A single new combined file is possible but should still expose an explicit staged/preinvoke boundary and a testable exact-native-command builder, rather than hiding the boundary in a proxy.

### Exact ordinary command/predicate changes

Remove EI's conditional Live→Right, all NAV/Apps preparation and `gates.apps_gate` calls. Do not substitute another key. Keep the public-gate command as is. Use the existing FU source-pinned `wake-check.py` **snapshot command and `parse_snapshot` only**: boot check/read, uptime, `vconftool get memory/eden/current_tab`, `enlightenment_info -topvwins`, finaluptime. Never call its `perform`, `wake_command` or `qualified` helper (the latter requires no saver and therefore expresses the opposite admission).

The candidate predicate must require exactly one canonical Live tab row, valid same-boot/ordered-uptime complete response, `screensaverWindowsPresent is True`, and `csfsWindowPresent is True`. Retain the complete bounded raw listing and derived summary. A malformed, duplicate, wrong/missing tab, truncated/oversized response or saver/CSFS disappearance refuses; no repair, wake, navigation, refresh key or bounded settle-with-key follows. Cached Live+saver is an observation, not proof of continuous UI state or optical saver activity.

## Fixed sequence and outcome boundaries

1. **Local dry admission before root import.** Rehash new manifest, existing helper/source/payload pins, full stable accepted EBfault40/logger0 from the exact16/32 family, raw files/result/inventory/envelopes, and explicit same-instance/phase lineage. Require Ready/released/closed/cleanupSTAGE_ABSENT and no pending IN/payload. Do not promote a refused pre-arm two-read result into this full fault-source contract. The original FW accepted fault EB illustrates the required family; it is historical after recovery and is not a current operation premise.
2. **Read-only initial UI/public admission.** Under central serialization, require current same-boot descriptor-bound identity and accepted phase provenance; take the strict Live+saver+CSFS snapshot and unchanged public rejects. Snapshot mismatch means zero helper staging/native invocation and no further UI action. Root response parsing remains strict and source-pinned. Snapshot age and identity are not continuous/atomic proofs.
3. **Stage the unchanged helper only.** Create its fresh private stage, pin hashes, preserve one-attempt intent and file caps. Staging failure stops with nativeInvocations0 or unknown only if an invocation was actually submitted; retain the stage and evidence as required by the existing helper. Do not classify planned staging as an actual ioctl call.
4. **Immediate pre-native guards.** After all staging, repeat the unchanged public reject call, then take a final strict Live+saver+CSFS snapshot. Each is one ordinary request. Record a host monotonic query-before/return bracket; require0..1second from final accepted query return to the subsequent fixed native root submission. This is host freshness only. Recheck boot/stock hashes in the original native command as before. There are no root/UI calls between the final snapshot and native submission. Any guard, clock or source failure stops before invocation and is never automatically retried.
5. **One unchanged fixed MODE2 invocation.** Set submitted/possibly-inflight state immediately before its one exact root command. Keep source/ABI/CLR checks, native alarm12seconds, root45/host75seconds, command8192 and root response65536 caps, exclusive managed receipt, separate stdout/stderr, strict ARM/root/fixed-request/return/close classification. Preserve ambiguity without fallback, replay or a second MODE2. The alarm does not prove interruption of uninterruptible kernel I/O or rollback.
6. **Terminal lifecycle classification and its existing file cleanup.** A successful helper path retains its exact receipt, native stderr/return and exact private helper cleanup. Failures preserve original outcome/stage; no key, reset or automatic retry is added. Keeping helper-owned file cleanup is distinct from UI/USB recovery and does not remove the old refused FN stage.
7. **Post-init cached-context check.** Take one strict Live+saver+CSFS snapshot after the accepted terminal helper. Context loss is a separately recorded postcondition failure even if ioctl/cleanup succeeded. Stop the candidate: no wake/navigation/repeatedMODE2 and no automatic vendor read to rehabilitate it. Further operational reconciliation, if required, is a separately coordinated action with its own record.
8. **Positive fresh instance and baseline.** Only after those gates, collect ordinary lifecycle/identity/census evidence proving the old instance disconnects then a new device enumerates on the same expected path/boot/descriptors, unbound with no observed holders. Do not infer exact event ages by subtracting kernel/dmesg and native clocks without calibrated mapping. Then prepare new EB readiness from the latest phase and perform one accepted fixed16/32 EB read. Require full clean40/logger0 start/end, M/root/geometry packing and actual values that the later FN full-first-clean guard accepts. Preserve zero-table/nonzero residual fields honestly; this is not a universal clearing test.
9. **Final admission for a distinct recorder.** Bind the new EB source/raw/phase/identity and context outputs. A recorder must again take its own read-only cached Live+saver checkpoint after its own staging, then arm only through its unchanged fresh clean/full-context guards. The present candidate performs no nativeLeft itself. No claim is made that Live+saver persisted continuously between snapshots or that later Left will be consumed as intended.

Expose separate outcome fields, for example sourceFaultAdmitted, nativeInvocations, nativeTerminalAccepted, helperCleanupConfirmed, postCachedContextQualified, newInstanceQualified and freshEbBaselineQualified. `initializationPrerequisiteQualified` requires all positives. A successful syscall with a changed tab/saver or faulted fresh EB is not successful baseline establishment. Use original physicalPictureObserved=false/rootCauseFixEstablished=false; no instruction-reload or allRAMcleared flag may become true from MODE2/EB alone.

## Finite mechanical qualification before any deployment

Source equality checks must show nativeProgram/threepayloads unchanged, exact original invocation/parse/cleanup bodies, no added ioctl or input_keyevent path, and only explicitly listed coordinator/staging-boundary changes. The new cached parser must accept Live+saver+CSFS and reject Live/noSaver, Apps/ForYou, absentCSFS, duplicate/corrupt rows and wrongboot. It must not reuse FU's no-saver `qualified` policy.

Mock exact stable fault admission and rejection for accepted=false, changed/partial raw, wrongmanifest, start/end divergence, threshold200, nonzero logger, unknownphase, missingrelease/close or incompletecleanup. Rejection happens before live root load. Test initial context/public failure before staging; disappearance/tab change after staging before native; age<0, age>1second and clockfailure before submission; successful source pins plus staged exact receipt; helper ambiguity/nonzeroioctl/close/error/timeout with zero retry; posthelper saver/tab change with original terminal success preserved and no EB submitted; changed/missingUSB instance proof; freshEB fault/Q/c4drift/nonqualifyingcontext. Both valid pre/post snapshots remain merely snapshots.

The positive full mock sequence must contain no key operation, exactly one fixed helper submission, current public rejects twice, three cached-context snapshots (initial/immediate/post), fresh identity/census and one EB only after admission. Compare every generated native/staging/cleanup command to DH, syntax-check all commands, and measure actual worst command/response/receipt caps. Keep native12/root45/host75 deadlines unchanged. Tests should also exercise a slow preflight so stale guards cannot be admitted after staging, and source/actualUSB66 binding without claiming it is a current fault. No broad historical replay or thousand-case sweep is needed for this host delta.

This package is a frozen design/source checkpoint only. It creates no deployable helper, calls no TV/root/network service, imports no top-level executor and changes no frozen files. The next implementer should produce the small host derivative and independently reviewed source/manifest before any central execution.
