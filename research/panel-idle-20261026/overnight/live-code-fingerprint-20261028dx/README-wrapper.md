# DX fixed sampled-code fingerprint reader

This host-qualified derivative of DM proposes exactly four read-only16-byte USB target0x101 pairs:0x46002020,0x4600bd58,0x4600c5d0,0x4600c1e0, in that order. It has no address argument, write operation, UI/reset/recovery action, fallback bank or retry. `--device N` only binds the existing fixed bus7/interface2/device identity to fresh readiness. The source author performs no target operation, publication or deployment.

The source-qualified bank comes from frozen DW: the selected image0 AP_EXCO lookup uses tag1 to read image1 resource/count/name pointers through0x460… and its context through0x470…. USB0x101 directly schedules the already-converted bus address. The four complete intervals are in the selected image1 low-code bank and are word-aligned; bd58 has8-byte alignment, not16-byte alignment. The read count is16bytes in every case.

USB DMA reachability for these code windows is experimental. The firmware's ordinary CPU resource reads do not independently establish this DMA master's accessibility. Success means only that the four sampled64bytes match selected-package SHA identities. It is not whole-image attestation, an observation of active instruction fetch, or proof of executable writes, cache visibility, scratch ownership, hook-install atomicity or rollback. No instruction patch or new code execution is generated.

NativeBinding.cs and Controller are inherited unchanged from the reviewed DM reader. The same fixed descriptor/boot/device/FD checks, local successful claim, three cached GETDRIVER/native filesystem ownership proofs, bounded clock/bulk handling, accepted-header matching-IN obligation, Unknown stop, release and close remain. The exclusive private receipt isolates structured JSON from native GC diagnostics. Native cooperative40s/per-bulk2s and root45s/host75s bounds remain; they do not promise termination of uninterruptible kernel I/O.

DX checks the exact expected SHA after every completed IN. The first mismatch is retained in the native receipt and stops further headers with ReadyForHeader if its full pair completed. A short or throwing transfer stops Unknown. No mismatch or transport ambiguity selects a different bank or repeats the read. Native acceptance requires4headers/8bulks, all4matches, ReadyForHeader and successful cleanup. `sampledCodeMatch` never implies `wholeRunningImageAttested` or `executableWriteQualified`.

The wrapper stages only the three pinned .NET payload files in a fresh private nonce directory, runs the zero-device-I/O fake selftest once, then one production invocation only after fresh exact identity/census/readiness. Success retains the four raw payloads, private native receipt and metadata, verifies final inventory/hashes, and removes the exact stage. Failure retains its evidence/stage for central reconciliation; a rejected result is not permission to replay or guess cleanup ownership. No target operation is made by host tests or manifest generation.

DW source/package identities are pinned in dw-source-pins.json; the selected package is SHA256 bad60bca4d6064406f14e53da3528d46701ec9c81673f4323db1937f6a2017e0. The tiny64-byte reviewed instruction excerpts in HostTests.cs are data used solely by FakeOps to exercise exact-match behavior; they are never executed as code. No whole OEM binary is copied to DX. verify_source.py verifies those excerpts against the retained package and the four DW hashes, plus exact inherited binding/transport/receipt source.

Reproduce using the retained .NET6 SDK and NuGet.Config, whose package sources are cleared. Build with task-owned HOME/DOTNET_CLI_HOME/TMPDIR. Run the DLL --self-test, python3 verify_source.py, python3 test-runner.py and python3 -O test-runner.py. Host production entrypoint must refuse64 before native/device calls. finalize_host.py rewrites only this derivative's deterministic fixture/checkpoint pins. run-once.py and run-once.py --print-manifest remain host-only; execution requires the exact reviewed manifest and a new dx-code-fingerprint-readiness-decision-v1 bound to current identity and centrally justified first-header lineage.
