# FN combined event recorder successor, host-qualified only

FN is a separate successor to the frozen FG recorder. It changes the interpretation of one positively source-qualified runtime field, verifies the final readback before reporting an already-zero restoration, and preserves a native refusal before any complete-ring check. No TV, root, network, USB, MMIO, threshold, kernel or firmware operation was performed to build or qualify FN. Its executable has not been deployed. FG, the actual FH trial, FL and FM remain separate frozen evidence.

The initial requirements remain strict: prearm requires C8=3, and the first full clean observation baseline also requires C8=3 before any Left dispatch. Later observation and fresh cleanup admit only the positively recovered stock values 0,1,2,3,4. This finite positive set is **not** a complete global value domain and does not prove which source path ran on the TV. A first full baseline with a qualified non3 value stops before Left and reaches the original fresh guarded cleanup. An unqualified C8 value still takes the existing semantic-error refusal path, which can retain logger1 and requires separate reconciliation.

## Bounded production changes

`successor-delta.json` enumerates every production edit after the FN family/assembly rename. `verify-source.py` reconstructs12 complete production files from the pinned FG originals and those explicit replacements, failing on any extra edit. It also checks the complete human-readable `production-diff.patch` artifact. It retains the versioned legacy `fg-stockevent-checkpoints-v1`58-byte row schema. `NativeBinding.cs`, `OnsetKey.cs`, `ScoreCheckpoints.cs`, `NuGet.Config` and FC's `wake-check.py` remain byte-identical to FG. The full scientific `key_exposure` function is also byte-identical, including optional R-only witnesses, successful down timing, and separation from protocol acceptance.

Engine changes are limited to the following behavior:

- `Context` admits C8 values0..4 at runtime and cleanup, while prearm's `initial` restriction still requires3. First-baseline C8=3 is explicitly checked alongside the existing first clean and scan1 conditions, before row retention and Left.
- A fresh cleanup R that already reports logger0 records `observed-zero-unverified`. Only a completed final R with the exact logger0/profile check commits `already-zero-no-write`. A short, failed, contradictory or upper-drift final read retains loggerMayRemain=true.
- The fixed root0x20010000, AA=0/AC=2, geometry2160/1920/2880, category92, C7<=1, scan0/1 restrictions, R logger halfword/profile, threshold40, alternatives, all pair and clock budgets, and all transfer-phase rules remain unchanged.

The original `phase==ReadyForHeader && !clockLost && o.Error==null` cleanup gate remains intact. No generic semantic-error recovery, guessed restore, retry, unknown-phase waiver or clock-failure cleanup was introduced. An invalid other context may still leave logger1 after refusal and needs a separate reviewed reconciliation owner.

The wrapper stores the checked native receipt and marks its status `terminal_receipt_retained`/`native_receipt_unparsed` before semantic parsing. After parsing it writes `primary-native-outcome.json` and a local record with the original error, cleanup/key error, logger restore/may-remain state and explicit Ready/released/closed lifecycle. On refusal it also writes `result.json` with accepted=false and protocolAccepted=false, then raises the primary refusal locally. It makes no subsequent root call, fetch, cleanup, UI call or invocation. Partial/empty post-ring metadata cannot replace that primary cause with a full-ring binding error. Known lifecycle and accepted observation remain separate claims.

The accepted path still fetches and checks both complete15372-byte ring sidecars, validates the unchanged wake checkpoint, and performs the original exact11-file cleanup. Structured receipt cap24576, stdout16384, stderr2048, root command8192, root response65536, native cooperative budget40s and root/host deadlines45/75s remain unchanged. Native observation still has a maximum56cycles,2s nominal window and25ms period, six cleanup pairs plus margin and key join reserve. There is one native owner, at most one native Left workflow after a qualifying first baseline, at most two logger payloads, and zero threshold writes. Arming/observation acceptance does not prove key causality, a physical picture observation, an event argument being the executing PC, or exclusion of ring wrap.

FN uses new native/manifest/readiness/result schemas and `/tmp/researcher-fn-<32hex>` stage naming. Its assembly is `CombinedEventSuccessor`. Running the wrapper with no arguments is dry. A future target action requires its separate reviewed manifest and current readiness premise; this host qualification is not a deployment or current queue proof.

## Reproduction and qualification

Run `sh build-host.sh` in FN. It uses the existing local.NET6 SDK and an empty NuGet source configuration. SDK home, NuGet cache and temporary files stay under FN's private `host-environment`; it does not use the small shared `/tmp` scratch for build output. All mocked root commands are checked for shell syntax and length; no actual root adapter is imported by tests.
