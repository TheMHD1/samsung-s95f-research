# In-process RTP checkpoint hook: exact sites and remaining deployment blockers

**An in-process logger can be specified at exact selected-code sites, but executable-RAM patching is not currently qualified.** The missing proof is the running instruction memory and its safe replacement/rollback mechanism. A successful SRAM data read or a fixed halfword configuration write does not establish either. This audit creates no executable payload, branch bytes, target package or deployment script, and performs no TV, USB, root or network operations.

The narrow diagnostic objective is to capture the actual comparator threshold and selected-A inputs at execution time, plus the fault setter's caller. Those are blindspots in the existing DM/DP snapshots. This is a concrete custom-logger design; its deployment remains blocked by the technical conditions below.

## What would be logged, and where

All addresses here are **selected image1 linked VAs**, with package file offset `VA+0x40200`. They are not qualified USB addresses for instruction memory. Package SHA256 is `bad60bca4d6064406f14e53da3528d46701ec9c81673f4323db1937f6a2017e0`. Static anchors, displaced-span hashes and register meanings are in `source-audit.json`. No whole running-code identity is inferred from the package-compatible callback generation or saved data layout.

The formatter choice reduces exposure compared with hooking **every lane** at comparator entry0xbbbc. That alternative has actual A/B inr0/r1, lane r2,row-like r3 and original-stack channel argument, but it also runs for lanes that never qualify. The static body preserves r8 after `mov r8,r0` atbbc0, except the function-return pop; its only other callee before formatter calls is the getter38fc, which uses r0 and returns without modifying r8. This is why the narrower formatter caller allowlist can capture A directly. It is not a proof of real-time overhead or the whole live ABI.

**Do not use a naive4-byte detour at0x202a.** It is only halfword aligned and would overwrite both a CMP and a PC-relative BLE. Copying that conditional branch to a trampoline without semantic relocation changes its target. The aligned0x2024 instruction is a better candidate for the observed non-mode6 path and has no PC-relative operand. This still does not establish atomic DMA replacement, instruction-fetch visibility or permission to modify that address.

## Bounded event representation

A proposed fixed64-byte event comprises a16-byte header (`u32 sequence`, `u16 kind`, `u16 payloadWords`, `u32 originalLR`, `u32 dispatchToken`) and at most12u32 payload words. No formatted strings, allocation, I/O, clock configuration, transport calls, fault clears or protection changes occur inside a hypothetical hook. Preserve full entry register values in payload even when the source uses only12 or16 bits; the decoder can apply the source mask.

Kinds have these minimal payloads:

- **Predicate:** mode, score register, threshold register, helper T and row/channel-like registers. This closes the actual-FP blindspot. A raw memory copy of H/q/history is optional additional work and must not be described as the comparator's exact pre-update state.
- **Selection:** actual A pointer, actual B pointer, row/channel-like registers. OriginalLR supplies fixed-top/fixed-bottom/dynamic provenance. Do not dereference an unqualified extra pointer merely to enrich a record.
- **Tuple:** original A register, B, lane, row, channel, stack difference and type, only at the four allowlisted caller returns. This closes the unsigned B±difference ambiguity directly. It does not by itself identify the physical producer of the packed data.
- **Setter entered:** event value; originalLR identifies the callsite. It is an intent/entry checkpoint, not an after-store completion timestamp.

A concrete initial capacity model is64 tuple records,16 predicate records,8 selection records and4 setter records, in disjoint fixed pools: **5888 event bytes plus64 control bytes =5952 bytes**. These are proposed capacities, not an allocated scratch address or a complete-capture promise. Give the setter pool reserved space so tuple saturation cannot erase the fault event. Never wrap or overwrite completed records; report per-pool saturation. The unchanged-40 run's41 source-compatible entries fit64 tuples, but a changed-limit run could exceed that pool. A saturated trace cannot prove absence of later events. Filling first8 selection records can also miss a later relevant dispatch, so exact pointer/tuple correlation needs a qualified shared dispatch token or a separately justified trigger/filter; row equality alone is insufficient.

A token must be produced at a known boundary and survive nested/reentrant calls without mixing contexts. The current design has **no qualified token implementation**. A plain shared global that increments atbd58 is unsafe to assume single-producer. No arbitrary controller timer is added: sequence orders admitted events only. DWT CYCCNT is optional architectural machinery whose existence, enable state, overflow and side effects are unqualified on this controller. A fresh timestamp must not be invented from the host poll time.

Write payload first and commit a sequence last; a collector should accept a slot only when two commit reads match and the whole payload fits the pinned schema. That is a proposed consistency protocol, not a proved cross-core/DMA atomicity guarantee. It requires established store widths, alignment, visibility/barrier semantics, producer ownership and a reader strategy that cannot race partial slot reuse. Nonwrapping pools reduce these obligations; they do not remove them.

## ABI, predication and liveness obligations

The original4-byte spans contain whole instructions and have no PC-relative operand. The bounded decoded function prefix at each candidate contains no IT instruction. The comparator function also has no decoded IT in the audited body. This is not a full control-flow census against branches into displaced instructions, an exception resuming there, a modified running image, or a live nonzero ITSTATE. A future implementation must close those cases against the actual executing code. It must never insert a branch in the middle of an IT block or use an existing literal/data pool as a code cave.

Save original LR **before** a link instruction could overwrite it. Original Thumb return addresses carry a state bit; allowlist comparison must preserve the actual return and normalize only the recorded/compared copy. At function-entry hooks, `[sp]` and `[sp+4]` refer to the original incoming stack, before any logger pushes. At internal0x2024, all registers and flags that the original continuation observes remain live. Preserve r0–r12, LR, SP and applicable APSR state; an arbitrary C helper call's caller-saved convention is insufficient. Avoid FPU instructions or callees unless FPU/lazy-stacking state and stack budget are independently proved.

Replay each displaced instruction exactly once with the original operands and stack. The common setter replays two instructions, not only its push. The unpacker's original52-byte push followed by its0xf1c stack allocation consumes **3920 bytes** before deeper calls. A logger cannot claim spare stack merely because its own event is small. Calling a helper must preserve the required stack alignment at that call; no alignment fix may change where the original function reads its incoming arguments. Disassembly equivalence, all arithmetic/branch flags and return paths must be tested under a target-ISA emulator or a stronger execution model before any target use. Current host tooling does not provide that qualification.

Interrupts, other core activity and watchdogs are unresolved. Per-event store count, bus wait states, entry frequency and exception nesting determine overhead. A64-byte record entails16 data-word stores before counter/commit updates, plus register preservation; no cycle-time bound follows from that count. The high-rate0xbbbc alternative could magnify overhead across many lanes. Do not disable interrupts across the observation interval, assume a debug halt is harmless, or feed/disable a watchdog for logging. A finite write budget stops record growth; the installed detour still adds work on every entry until it is safely removed.

## Deployment blockers and concrete qualification artifacts

1. **Executing instruction mapping and identity.** Trace the actual loader/remap or positively establish the live code alias for image1 low VAs. Retain same-boot exact original bytes around every site and proposed trampoline. The existing data mapper proves only its specified SRAM range; CPU code VA2024 is outside that range. Raw numeric VA2024 is not a qualified USB address. Reset-vector-shaped words and package/callback identity do not establish SRAM-backed executable storage.
2. **Scratch ownership and execution attributes.** Recover a linker/allocator reservation or an equally strong owner proof for5952 bytes plus code/context, along with lifetime, aliases and bounds. Prove writable/executable memory attributes, any SoC remap/cache/prefetch behavior and interconnect visibility. A run of zero bytes is not free memory. Neither the logger ring nor the RTP arrays are available scratch by assumption.
3. **Installation/removal atomicity.** Establish a controller-local safe point, documented debug facility or other proven mechanism that prevents instruction fetch through a partially installed/removed detour. A4-byte Thumb instruction consists of two halfwords; alignment and USB transfer success do not establish atomic code replacement. A generic multi-header install cannot be treated as a transaction. Trace required barriers/cache synchronization for the actual core/SoC, not a guessed CPU class.
4. **Exact hook implementation proof.** A future offline artifact must include a pinned target assembler/toolchain, source and disassembly, relocated-span equivalence tests, original LR/SP/flags/register preservation, nested/interrupt scenarios, all slot-full paths and bounded worst-case stack/time. No such payload is generated here. Run the event decoder against malformed/partial/saturated synthetic rings before considering installation.
5. **Independent bounded rollback.** The current USB protocol permits an ambiguous short transfer to prevent any further safe header. Thus host `finally`, process timeout, readback, or a separate restore command cannot guarantee code removal. A controller-resident disarm budget only disables logging; it does not restore overwritten code. Self-unpatching introduces its own fetch/atomicity/concurrency problem and is unqualified. Require a recovery path that remains effective when the host/USB link fails, proves original bytes and visibility, and does not depend on a watchdog reset, boot or firmware rewrite being harmless.

Until those artifacts exist, **no executable patch, breakpoint trap or new code execution is technically qualified**. This is a proof gap rather than missing user authorization. A failed low-level experiment could stop display/power servicing; that material risk follows from altering executing controller code, without inventing a specific persistent failure mechanism.

The retained [Arm Cortex-M4 TRM](https://documentation-service.arm.com/static/5f19da2a20b7cf4bc524d99a) describes instruction/barrier behavior (chapter3), optional debug hardware (chapter8) and FPB (section8.3). FPB is a possible alternative to modifying an instruction stream only if the actual implementation supports patch remapping, available comparators, mapped replacement memory and a safe ownership/rollback protocol. Some implementations have only breakpoint comparators and no flash patching. Breakpoints can halt servicing; FPB/debug-monitor/MMIO writes are not proposed as a shortcut. The retained [CMSIS6 core_cm4.h](https://github.com/ARM-software/CMSIS_6/blob/99072a3bf70578394bea9dba511922d2961007f5/CMSIS/Core/Include/core_cm4.h) supplies architectural register definitions, not proof of target features or safe access. Both sources were read locally with their original acquisition pins; no network was used.

## What current evidence can answer first

DP supplies a sampled score38→42 transition and software R fault bracket, with actual decision-time FP unknown. DM supplies sequential qualifying-record B/difference/coordinates and ordinal41, with epoch and fixed-A branch unproved. DR source-qualifies limited fixed12-bit top/bottom reference windows; even exact matches would show data compatibility at those later read times, not the pointer actually chosen or value actually compared. The proposed hooks close those particular execution-time gaps; they would still not locate the physical packed-data producer, measure panel light or prove that any protection threshold is electrically safe to raise.

The immediate source task is therefore the loader/executable-alias plus scratch/rollback proof, while existing bounded captures remain useful for narrowing the A-data hypothesis. It is not another expansion of arbitrary RAM polling or a claim that the current observer already instruments comparator calls.
