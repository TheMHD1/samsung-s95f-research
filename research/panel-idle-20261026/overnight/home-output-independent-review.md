# Independent Home/output review and correction record

Reviewed offline by a separate read-only agent against the matching binaries, with parent cross-checks. No TV setters were used. Findings were incorporated into the reports; this record keeps rejected interpretations visible rather than silently preserving them as facts.

1. **Registration table field order.** The proposal that SetNewHome was0x3d5ac and ResetSpecialModes0xc1524 was false. The consumer at avocd0x7b7c4 uses tablebase0x172dd4, word0=name (r1), word1=callback (r2), stride8. SetNewHome entry0x173c84/88 resolves0xc1524; GetDynamicPeaking is0x3d5ac. Original mapping restored. Parent saved `avocd-handler-registration.disasm`.
2. **FRC request word order.** Actual libave request is `{selector=3,value=enter}`, eight bytes, ioctl0xc00866ff. It reaches FRC_Request, not similarly named FRC_NewRequest. Any reversed prose was corrected.
3. **Monitor enable helper.** `ave_tcon_monitor_onoff` changes monitor-on/saved-previous and restart flags; it does not directly signal the condition variable. Nominal one-second timed wait belongs to the actual monitor thread; the roughly one-second later visible-state reporting interval is independent measurement.
4. **Central operation-table handoff is present.** `init_frc_tcon_driver` in the copied API at0x7c78 calls FRC table slot0 with the registered TCON table at0x7ce4. Rosem slot0 is InitVariable, which stores that pointer; the claim that its caller was absent was false. This proves static initialization wiring, not a live incident pointer read.
5. **Raw rate is not0x15c payload.** QDF SetVRRFrameRate caches raw centi-Hz rate then derives frame mode0/1/2. Frame mode programs0x160. VRR-control scalar at BSS+0x130, not the raw rate, feeds0x150/15c.
6. **Frame-mode bracketing is the same QD mute command.** `m_tcon_set_frame_mode`0x10508 uses exactly the F3:0x164/mute1 or0/lock1 tuple used by `QDFTcon_t_Tcon_SetMute`. Its guard uses the same cached `m_mute_state` at BSS+0x140. It skips both brackets when already cached muted, and otherwise does not update that cache for its temporary bracket. The earlier claim that this deep timing edge did not reach mute, or that its vendor mute semantics could not be named, was false.
7. **No omitted returning cleanup branch was found.** For the bracketing path every returning normal/error branch attempts mute0 at0x1074c: initial mode already matches, successful programming, and retry after mismatch all converge. The50ms delay is on the bracketed path; the500ms delay is only in the programming branch. Initial mute1 rc can be overwritten by the mode-write rc at0x10614.
8. **Failure and de-duplication boundary.** Final mute0 can itself fail. The lower routine accumulates that return, but m_tcon_set_frame_control ignores it and QDFTcon_SetVRRFrameRate returns0 unconditionally after caching the raw request. Mode is also cached before programming; Rosem remembers its selected rate. A host success/cache reading therefore does not prove successful hardware unmute or mode acceptance.

9. **All historical terminal thresholds retained.** The terminal fault-latch condition includes ERR_DET reboot+0x48>1, VDD reboot+0x4c>3, **and ELVDD reboot+0x50>3** (third comparison0x269ae6..269aea). The originally omitted third condition was restored. The historical timing report now links the configured outer cadence while keeping onset timing unmeasured.

Item8 is a concrete plausible mechanism for a hidden gate mismatch, not an observed explanation for the owner's blackout. No aligned gate-on/off transition has yet been captured. It strengthens the already prepared single public unmute-zero diagnostic, which reads live mute status and can re-send zero; that diagnostic remains unexecuted without fresh physical observation. It does not justify bypassing fault handling or installing a repeated recovery loop.

Final independent review additionally verified the QDDimming and QDDimmingMNT vtable+0x158 base zero-returning query stub, QDMNT backend+0x210 APL-filter no-op, and+0x200 real screen-saver backend. Its final low-priority stale-phrasing comments were reconciled against the parent’s concurrent propagation edits; no unresolved binary disagreement remains in the reviewed claims. Incident causation and physical recovery remain unverified.
