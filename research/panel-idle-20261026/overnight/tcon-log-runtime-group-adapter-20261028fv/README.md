# FV: exact runtime debugfs mount-group qualification

FV is a narrow additive derivative of the independently reviewed immutable FP adapter. It reuses FP's lifecycle code, staging, framing, parser, fixed FK payloads, and cleanup in place. It does not rebuild a native binary or change FP/FK. The sole target-command delta is the exact `/sys/kernel/debug` directory stat guard from root UID0/GID0/mode0755 to root UID0/GID100/mode0755. Symlinks are still refused. The TCON subdirectory, log node, on-disk module, boot, kernel, mount, root caller and all remaining guards stay exact.

The reason is the separate FS metadata observation. The original FP attempt refused during preflight, before staging or a native/content read. A subsequent separately planned metadata-only request measured the debugfs mountpoint as UID0/GID100/0755; every other checked runtime premise matched. FS retains its original refusal. The later mismatch is source-compatible with the failed guard; the original command did not print its first failing statement. No directory ownership is changed to satisfy a test.

FV loads the pinned FP pure module, retains its original functions, and substitutes two bounded metadata functions. The command builder requires exactly one original mountpoint guard before replacing it. The parser first requires the first directory row exactly `0:100:755`, then normalizes only that row for the unchanged FP parser. The original parser continues to check every other row. GID0, GID101, nonroot UID, other modes, changed TCON ownership and inconsistent runtime values refuse. This is not a generic group or path option.

The composite FV manifest binds its own source, the exact FP inventory/manifest/independent review, fixed FK checkpoint and separately retained FS metadata. During execution the unchanged FP lifecycle records that composite manifest. `result.json` retains its honest FP delegate schema, while the additive `fv-result.json` identifies the derivative and hashes the base result. A base result under FV must not be described as satisfying FP's original GID0 guard. Exceptions propagate with original refusal artifacts and no derivative success result or additional target request.

Default invocation is a zero-I/O dry report. Execution requires `--execute`, the exact FV manifest hash, FK checkpoint hash and fresh absolute output directory. No target/count/stage/address/timeout argument exists. The target remains one fresh open, one direct read requesting/allocating4096, and one close attempt. Root45s/host75s, command8192/response65536, native receipt16384 and all file/framing caps remain unchanged. No retry, seek, ioctl, initializer, ACK, printer, UI input, USB transaction, driver write, module load, kernel, boot or flash write is introduced.

Read-only acquisition still does not prove complete copy, fresh/complete log, atomic producer view, loaded-module instructions, an external RTP producer bridge, physical picture, timeout closure or rollback. All original limitations and private0600/0700 raw retention apply. Only the six owned ordinary stage files can be removed after accepted integrity checks; refusals retain the stage and do not automatically retry or clean up.

`qualify.py` runs without importing the live root transport. It pins the actual retained runtime metadata, compares old/new complete commands byte for byte, tests all candidate groups0..200 and other ownership/runtime negatives, and mocks full/short/zero accepted reads, wrong-group preflight refusal, native ambiguity and native refusal. It verifies separate derivative provenance, private raw retention and no follow-up request on refusal. Source/normal/optimized outputs, exact checks and inventory are sealed after qualification. Independent review is required before a target run. This directory has performed no target/root/network operation.
