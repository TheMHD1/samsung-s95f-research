# Fixed Live-header derivative around frozen FN

This host-only adapter implements the frozen FT Live→ForYou design. It reuses the exact FN DLL, deps/runtimeconfig and strict native parser **in place** under `../combined-event-successor-20261028fn`. There is no native rebuild or new payload. FN native schema and `/tmp/researcher-fn-<32hex>` stage contract remain FN. The new wrapper, readiness, wake and preparation schemas are FU and record `expectedCachedTab=Live`, `intendedNavigation=Live-header-to-ForYou`.

`prepare-live.py` is a separate, dry-default operation. It accepts only a canonical cached Live snapshot. An initial saver permits one fixed ordinary volume wake, followed by at most ten cached snapshots. It then sends exactly Up / settleLive / Up / settleLive, each settle capped at ten snapshots with 250ms between unsuccessful snapshots and a ten-second cooperative phase budget. Accepted snapshots require no saver and CSFS. Unknown/malformed/duplicate/other tabs, failed key exits, exhausted settling, clock errors or ambiguous calls stop without another key or fallback. This preparation sends no Left and no controller command. Its intent, each exact command and raw response, monotonic clocks, source hashes, summaries and completion counters are retained in a private separate ledger. Successful key exits do not prove UI consumption or compositor focus.

The wrapper requires that preparation certificate, its digest, the sealed FU manifest and the exact certificate reference in fresh FU readiness evidence before importing the root adapter. `prepare-readiness.py` validates the certificate locally and includes it in its evidence; it is dry by default and requires `--execute` for its single ordinary cached metadata operation. Its identity/census and the parent's explicit closed-world vendor lineage remain prerequisites, not queue proof. Preparation never substitutes for fresh wrapper admission.
