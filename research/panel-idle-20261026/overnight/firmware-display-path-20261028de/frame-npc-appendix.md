# Additive frame-mode and NPC source closure

This host-only appendix preserves the initial DE report and graph. Controller addresses below are selected image0 linked addresses (FILE=VA+0x200), not Linux runtime addresses or a live-code hash. Exact sources are pinned in the additive inventory. No target action, setting change, network access or OEM execution occurred here.

The cadence hypothesis has two concrete negative constraints. First, the exact chip14/non-monitor QDF branch with low-input-lag other than1 requests controller mode0 for raw rates2400,5000,6000 and12000. Raw14400/16500 requests mode1; low-input-lag1 requests mode2. Thus changing24Hz to60Hz need not change this controller selector. Second, the upstream AP+0x37a comparison feeding AP_EXCO's second SLG predicate is masked **off** in both the packaged initializer and the older W ordinary snapshot: AP_EXCO+0x2cc=1, +0x2ce=2, so bit0 is zero. The four comparison constants+0x2d0/2d2/2d4/2d6 are zero. The W sample is older than DH and does not establish the present mask. It also has+0xe6=1 versus initializer0; matching configuration fields do not mean the entire states match.

These facts weaken a direct “24fps→AP frame mode→SLG” fix proposal. They do not eliminate other content/cadence/HDR paths, including NPC or histogram-tail inputs. Existing incident evidence has working23.976 examples and failures involving both Home and HDMI; one title's frame rate cannot explain all controls.

## NPC resource reaches a distinct controller object

The selected AVE resource `usr/bin/ave/pq/LUT_NPC_Point.json` SHA256 `e13048126ad19d6890ef8c862abacc682645de4bf8131f9f97a05dc3baef3ce3` has16 command entries per table, addressing F300 selectors0x007c..0x00b8 step4. Initial DE already traced content/state selection and the16-command loop. The receiving switch entries0x2cb32..0x2cb50 include NOP fallthroughs into **one common store**; they are not ignored/no-op commands. At0x2cb50..2cb60, index=`(selector−0x7c)>>2`, value is masked to10bits, and a u16 is stored atNPC_AP+0x2ae+2*index.

The resource registry in this image distinguishes NPC_AP rootCPU0x2000d71c, length0x540 (directory row0x3caf4), from AP_EXCO rootCPU0x2000ff14, length0x33a (row0x3cbd4). The16 NPC stores therefore reach CPU0x2000d9ca..0x2000d9e8. A same-named numeric offset in AP_EXCO cannot be substituted. The bounded consumer at0x19c2c reads NPC_AP's table selected by u16+0x86, with additional table/endpoint interpolation logic. The source closure to AP_AG+0x92, AP_EXCO histogram thresholds or the packed RTP payload producer is still **unknown**. No NPC setting change is justified solely by this RAM destination closure.
