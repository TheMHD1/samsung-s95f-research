# Fixed volatile limit comparison

This host-built experiment writes only target 0x102, address 0x470124c4, length two. `--action set` selects 40→200 (`c800`); `--action restore` selects 200→40 (`2800`). The native header is `02010000c424014702000000`. Each invocation performs one action, no UI, reset, hold, automatic restoration, retry, background process, or caller-selected memory operation. This is an experimental policy comparison, not an established root-cause fix or electrical safety proof.

The transport and ARM USB ABI derive from the reviewed DF observer; the exact write-pair obligation derives from the successful V6 two-byte logger write. No target operation was performed to build or test this directory. Real execution requires an explicit ARM32 architecture and root UID/EUID. The native fixed action also requires `--device N`, a decimal 1..127 copied only from the reviewed readiness identity; cached devnum must equal it before open and its receipt is bound back to that identity. Full cached preflight is repeated after FD validation before claim and again after claim before the first header. This detects a re-enumeration to a different number between wrapper and native preflight; all snapshots remain non-atomic. Default wrapper and native modes are dry. `--self-test` and both `--host-fixture-*` paths use fake operations only.

Seven transactions: callbacks64; R256; M68; C16; fresh R256; write header/payload; readback R256. Before the fixed write: selected callback tuple, full R profile, clean stop/fault, ordinary gate1/logger0, mode1 root/geometry/numeric profile/scan enabled, disabled alternative event344/351 and aggregate gate1, expected starting limit. Full R compares every byte against a retained clean DH profile except named action-bucket/record/q latch regions and the mutable limit. Byte R+ca is permitted only at either observed clean value 0/1, must agree between baseline/fresh/readback, and is deliberately not assigned an unproved semantic name. Every non-status byte must remain identical on readback except c4. Historical record fields are not assumed zero; alternative-event latches are required zero. Geometry and C selector are source-qualified, with selector0/1 accepted; the write changes neither.

Every exact OUT header obliges exactly one corresponding IN or two-byte OUT. A pre-header timestamp failure refuses OUT immediately; a timestamp failure after an accepted header is recorded, completes the matching transfer, then stops. Deadline/clock failures cannot strand a known accepted header by suppressing that matching transfer. Any short, failed, throwing or ambiguous transfer leaves `Unknown` and sends no subsequent header. No automatic restore follows failure. Release/close are each attempted once for resources actually acquired; rejected/ambiguous results retain remote staging for centrally coordinated reconciliation. The software guard and write are sequential observations, not an atomic freeze against controller activity.

Wrapper execution requires a reviewed manifest SHA and a fresh parent decision using `dj-fixed-limit-readiness-decision-v1`. The decision distinguishes root census/metadata plus closed-world vendor-OUT lineage from endpoint-queue proof. The reused census accepts the exact target stat ENOENT churn syntax and rejects holders/other errors. Root input/upload uses the same reviewed bounded base64 staging, source integrity, private stage and exact cleanup rules; source/root loader hashes are rechecked before any connection. Native40s, per bulk2s, remote45s, host75s, one invocation, stdout24576 bytes. The strict offline parser independently checks schemas, action, every exact count/phase/timestamp, callbacks, raw lengths/hashes, profile and readback; native exit0 alone is insufficient.

It does not prove electrical safety, that 200 is suitable for all content, running-code identity, restoration after an ambiguous USB transaction, or permanent/persistent behavior. A latched stop/fault cannot be repaired by this helper: clean preconditions reject it.
