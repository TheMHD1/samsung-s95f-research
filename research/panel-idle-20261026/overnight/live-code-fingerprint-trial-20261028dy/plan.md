# Live code fingerprint: bounded coordinator plan

This is the next custom-debugger prerequisite, separate from the completed
DK data-limit comparison. The first proposed production request is still
pending. There is no target operation in this document.

The source-qualified DW plan permits exactly four16-byte image1 windows:
bus0x46002020,0x4600bd58,0x4600c5d0,0x4600c1e0. The reader must use USB
target0x101, complete each accepted header's matching IN, and stop after a
short, failed, ambiguous or hash-mismatching result. No bank fallback, retry,
write, key, reset, trap, breakpoint, instruction patch or memory scan is part
of this probe. New DMA reachability remains experimental.

Before a target request, freeze DX's implementation, native build, strict
parser, wrapper, source inventory and host tests, then obtain an independent
review. The parent is the only target coordinator. Cached device identity,
same boot, descriptors/configuration and holder census must be freshly checked;
the helper must prove ownership on its own successfully claimed FD.

The current closed-world protocol predecessor is DK/dv-final-clean-01:
accepted DM,12 complete read pairs, ReadyForHeader, released/closed and exact
stage absent. Its final actual limit is40 with clean stop/fault/gate0/0/1.
USB instance60 was current at that completed boundary. No new target helper
has run since it. A fresh metadata check must not be represented as proof of
endpoint queues or continuous absence of other clients.

If all four fixed payload hashes match the pinned selected package, record
sampled-code correspondence and ordinary USB DMA readability at those exact
windows for that capture. Do not infer whole-image identity, active fetch
mapping, code writability, scratch ownership, atomic replacement, instruction
visibility, a deployed logger or a safe rollback from that result.

Any preheader refusal preserves the refusal and its actual transfer count.
An accepted header remains an obligation even after a timing error. Unknown
phase forbids a new header or blind recovery. Cleanup follows the reviewed
helper's accepted-only policy; retain exact stages and evidence when it
refuses, and decide any subsequent action from the actual receipt.

No field is changed and no experimental limit is enabled by this probe. Its
purpose is to close one concrete barrier to execution-time logging at the
score predicate, selected-pointer entry, tuple formatter and common setter.
