# DF eight-window onset recorder and strict wrapper

This additive candidate extends the frozen BX recorder with fixed P/N windows. It was built and tested on the host only; target executions by this work are zero. Previous BX/CB files and the initial DF host-only prototype remain unchanged. The new native schema is `managed-usb-rt-synchronized-key-df-v1`; its transport parser is a separately derived and hash-pinned source, not the unchanged six-window parser.

Cycle: R,M,C,P,N,H,L,R. Post set: M,C,P,N,H,L,R. P is0x47000490/16, N is0x4700ba28/36. Exactly these two windows are added. There are no aperture or extra MMIO reads, pointer dereferences, threshold writes, firmware commands or reset. The original single USB reader, accepted-OUT/matching-IN behavior, no retry,20s/80cycle limits, nominal250ms cadence,2s transfer bound, one bounded Left worker after the first full clean cycle, cleanup, and immutable trigger baseline are retained. The pointer window reports dynamic slot pointers; it cannot prove the final A buffer on a fixed-buffer branch.

## Source qualification of the new fixed reads

Selected image1's resource translator VA0x1bb74 maps SRAM CPU0x20000000..<0x20020000 to alias0x47000000..<0x47020000 in mode1. Both P and N lie fully inside this range, alongside the already captured M/C/H/R/L data. P maps CPU0x20000490..49f, exposing pointer words494/498; N maps CPU0x2000ba28..ba4b, exposing sixu32 qualifying-record ordinals and sixu16 source counts. The anchored dispatcher/count source verifies these fields and widths. Headers are exactly `010100009004004710000000` and `0101000028ba004724000000`. The new36-byte IN length is explicitly included in the native fixed-length allowlist; all replies require exact requested lengths. No semantic meaning is assigned to neighboring P words.

This is source qualification of address range, intended layout and protocol request construction. It does not assert a previously observed36-byte device reply or complete live executable attestation. Under the parent's fresh first-header premise, the first new P/N pair provides exact length/count validation in the normal read loop; any short, failed or unexpected pair terminates the trial without a following header or retry. There is no separate speculative prerequisite read. A source/layout interpretation remains conditional if the complete running image has not been attested.
