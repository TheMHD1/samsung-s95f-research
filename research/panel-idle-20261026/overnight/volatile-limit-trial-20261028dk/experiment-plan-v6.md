# Revised finite RAM comparison after dynamic-profile source qualification

This additive plan supersedes the held DQ writer proposal, not its preserved
results. DQ never executed. DU now supplies a source-derived integer endpoint
model plus a deliberately restrictive mode1 admission policy. It does not
claim both endpoints are always refreshed together. Immediate post-init mode6
counterexamples remain retained; a fresh normal Apps capture admission-clean-01
passes DU with clean actual40, aa0/ac2, both endpoints3161, diagnostic24 andecho0.

The new DV writer must finish independent review before target execution.
It derives from DQ, preserves the exact fixed target0x102/address470124c4/length2,
set40→200 and restore200→40, callback/binding/phase/deadline/receipt/cleanup guards,
and every other pinned profile byte. Only the three source-modeled thermal
halfwords and semantically bounded echo replace static equality. Within each
transaction, baseline/fresh/readback thermal tuple and nonstatus state must
remain stable; legitimate variation between separate set/restore invocations
is accepted only through the exact model. No caller-selected value/address exists.

1. On verified Apps/header and current USB60, retain fresh cached identity/census,
   latest completed-pair lineage and final independent DV review. Execute one
   DVset. Require exact7headers/14bulks, readback200, closed ReadyForHeader and
   stage cleanup. A refusal is not success or permission to replay.
2. Only after accepted set, renew DP readiness from those completed pairs and
   execute the unchanged native one-Left20second/80cycle recorder. Require its
   initial clean baseline, one completed key workflow and all native lifecycle
   checks. Classify actual c4 values, C7/mode, A0 low16/history/q/source counts.
   A clean sampled score>40 under compatible alternate context is a useful

3. If the test is clean and phase/ownership/children are positively complete,
   select Apps by the calibrated normal route and execute a separate fresh
   DVrestore only after its own live guards. Require exact readback40 and cleanup.
   Preserve any post-test read-only data needed before restoration without
   inventing a common epoch. Bound200 permits publication0..200, whereas the
   current first48 arrays cannot represent the entire potential record set.
4. If faulted, retain DT reference/record data before separate Apps-selected
   stockMODE2 recovery. Fresh enumeration and actual RAM readback decide whether
   restoration is needed; never assume reset restored40. Clean-only DVrestore
   intentionally refuses a latched fault/scan0.
5. A known-phase clean prewrite restore refusal can require a separately reviewed
   operational stock reinitialization to leave the experimental value, followed
   by fresh identity and actual RAM verification. This is not an implicit action
   in DV. Any short/ambiguous transfer, Unknown phase, missing child/receipt or
   unresolved ownership stops new headers, retries and blind resets pending
   positive central reconciliation.

One finite exposure is authorized by this plan. Do not convert a20second result
into permanent prevention, a physical repair, or a persistent installation.

part of this comparison. The fixed field also controls record publication, so
